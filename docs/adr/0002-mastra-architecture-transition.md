# ADR 0002：由历史路线 B 转入 Mastra OSS 主线

- 日期：2026-11-26。
- 状态：总控已完成架构和技术选型裁决；本 Draft PR 待审核及合并。正式公共宿主和业务均未获施工批准。
- 生效范围：合并后替代 [PR #14 的旧主体选型](../archive/route-b/designs/whole-product-decision.md)作为后续设计/准备依据；不追溯否定历史裁决，不授权开发、部署、采购或流量。
- 唯一现行设计入口：[当前架构与实施门禁](../designs/current-architecture-baseline.md)；[施工记录、H1/H2 证据与校验入口](../tasks/architecture-baseline-transition.md)。

## 情境与决定

此前的路线 B（Python、PostgreSQL、Temporal、Pydantic AI）有真实局部可靠性证据，但较多上层应用工程仍需建设。后续 F01/F02/F03 以最终效果与成熟应用能力复用为先，不保护旧投入。F03 v1.1 保留 Mastra OSS/Server/TypeScript/Node.js 主体、必要公共治理及限定 Temporal 固定流程；F04 修订和 H1 顶层动态任务的限定机制试验支持使用原生运行循环、检查点和响应回放，不自研第二运行核。B02 后端不存在的事实由项目方确认，必要公共宿主从零建设。B03 本地操作与预算合同设计明确。B04 的 H1 负例保留；H2 的签名批次、旧版关闭和从合法来源干净重建支持限定采用 WeKnora v0.9.1。

旧 B、Agno 等历史候选作为证据和有限反转参考，不并行部署、不重新启动全候选竞赛。选型不是保护现有技术：遇到故障先查根因、官方仓库/修复及成熟团队解法，优先原生能力、配置与合理适配，必要时验证；确实不能满足必要能力或维护代价不可接受才局部改判。适用的通用规则由独立的 [PR #26](https://github.com/zhuquanwei111/mingjing---agent/pull/26)承接，该 PR 当前尚未合并，本次不重复修改规则正文。

## 验收方法与后果

需求 v0.4.1 原件及 FR01–41、NFR01–11、TS01–07、AC01–17 不改写；原 23 组/76 个编号、冻结判据及历史证据保留。可靠外部工程证据、已有试件、固定版本源码可支持合理选型；不强制重测全部候选，但不能降低安全、质量、可靠性、可维护性及正式验收。对实际采用的组合完成 H/W0a/W0b/G，G 全部必要公共能力实际通过后才开始 M。T/P 另行放行。H1 合成收端验证不等于生产或模型质量通过。

知识域按授权范围分区；每个版本固定来源、编译批次及父预算，所有物理出站先准入再发送，撤回关闭旧版并仅重建受影响域。多活动批次、实际费用和知识质量按 G 验收。若真实质量或重建开销超过批准边界，或必须重写知识核心，只提 A07 局部反转。详见[完整实施契约](../designs/architecture-final/contracts.md)。

本 PR 归档文档、图、映射及工程证据，保留原件和旧实现。回退本 PR 只回退仓库文档，不能自动恢复旧路线开发权。项目方审核后另行决定公共宿主建设授权。
