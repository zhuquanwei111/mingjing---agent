# ADR 0002：由历史路线 B 转入 Mastra OSS 主线

- 日期：2026-11-26。
- 状态：主体选择已获总控确认；文档基线变更待本 PR 独立审查与人工合并。完整架构仍条件性，B04 未完整准入，正式实施暂停。
- 生效范围：合并后替代 [PR #14 的旧主体选型](../designs/whole-product-decision.md)作为后续设计/准备依据；不追溯否定历史裁决，不授权开发、部署、采购或流量。
- 唯一现行设计入口：[当前架构与实施门禁](../designs/current-architecture-baseline.md)；[任务、H1 证据及未决清单](../tasks/architecture-baseline-transition.md)。

## 情境与决定

此前的路线 B（Python、PostgreSQL、Temporal、Pydantic AI）有真实局部可靠性证据，但较多上层应用工程仍需建设。后续 F01/F02/F03 以最终效果与成熟应用能力复用为先，不保护旧投入。F03 v1.1 保留 Mastra OSS/Server/TypeScript/Node.js 主体、必要公共治理及限定 Temporal 固定流程；F04 修订和 H1 顶层动态任务的限定机制试验支持使用原生运行循环、检查点和响应回放，不自研第二运行核。B02 后端不存在的事实由项目方确认，必要公共宿主从零建设。B03 本地操作与预算合同设计明确。B04 实测负例需要定向解决，未裁决更换 WeKnora。

旧 B、Agno 等历史候选作为证据和有限反转参考，不并行部署、不重新启动全候选竞赛。选型不是保护现有技术：遇到故障先查根因、官方仓库/修复及成熟团队解法，优先原生能力、配置与合理适配，必要时验证；确实不能满足必要能力或维护代价不可接受才局部改判。适用的通用规则由独立的 [PR #26](https://github.com/zhuquanwei111/mingjing---agent/pull/26)承接，该 PR 当前尚未合并，本次不重复修改规则正文。

## 验收方法与后果

需求 v0.4.1 原件及 FR01–41、NFR01–11、TS01–07、AC01–17 不改写；原 23 组/76 个编号、冻结判据及历史证据保留。可靠外部工程证据、已有试件、固定版本源码可支持合理选型；不强制重测全部候选，但不能降低安全、质量、可靠性、可维护性及正式验收。对实际采用的组合完成 H/W0a/W0b/G，G 全部必要公共能力实际通过后才开始 M。T/P 另行放行。H1 合成收端验证不等于生产或模型质量通过。

若 H2 形成上游修复、成熟扩展或受控批次的可维护方案，保留知识主选并安排适用实际验收；若不成立，仅按证据审查知识层替代，保留独立主体。其他必要路径若失效也先解决实际问题，不以屏蔽全部必要能力宣布通过。大面积重写成熟核心、长期 fork、重复建设管理或运行平台须独立复审。

本 PR 只变更文档入口及历史状态，旧 Python/P1/P2 代码、锁文件、CI 与所有分支保持。回退文档 PR 仅回退导航和决策记录，不能自动恢复旧路线的开发授权。最终获准完整架构、归档原件、实施授权与新 CI 由后续实际任务记录。
