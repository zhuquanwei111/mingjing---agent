# ADR 0001 以独立目录维护可移植工程规范

- 2026-11-23，拟议接入。维护者在专用 Draft PR 审核。
- [任务记录与独立方案评审处置](../tasks/engineering-standard.md)。

## 情境

明镜已有计划、审查、合并与真实 ARM64 验收。现有配置 Draft #3 包含恢复入口和架构守护。此次需要一种可从首个项目带走的版本化规范，同时保留明镜项目自身的业务和阶段规则。

## 选项与决定

- 仅扩充根规则和项目手册的初始改动较少。复用者需要从业务资料中手工抽取标准，版本与边界难以追溯。
- 单设外部标准仓库、插件分发或同步流水线能独立发布。首个真实采用项目只有明镜，增加维护、授权、分发和一致性成本。
- 选择在同一 Git 里维护[独立版本目录](../../engineering-standard/README.md)。通用规则、模板和技能保持目录内自洽。Python/Make/GitHub 是可选适配。项目根规则、运行命令和证据接入[明镜实例](../engineering-standard.md)。用一个符号链接接入仓库技能，用已有脚本验证文档和技能接入。

交付分支以 #3 的已核对提交为基线、指向其任务分支，独立提交和验证当前差异。基于 `main` 直接开发会与 #3 同时改动导航及验证入口。发布时显式推送本任务分支并核对 PR 目标与差异。若 #3 变化、合并或删除，由维护者授权后重新检查/调整目标，复核集成结果和正式门禁。

## 后果与复核

版本使用目录变更日志与 Git 提交定位。新项目可只取目录并适配自己的规则。符号链接不可用时可以按同一版本安装技能副本，保留唯一可发现定义。CI 沿用项目现有工作流的检查范围和服务器规则。Mac 冷恢复、独立代码审查及同候选的 ARM64 运行分别存证。方案评审选 CLI 阶段入口，固定 Git 快照与计划，拒绝异常后启动实施命令。工具钩子出现超时或协议异常时可能继续调用。阶段入口无需修改本机或项目的权限配置。Space 通过链接引用 Git 和协作草稿。

需要撤回时，在任务分支撤销本 PR 的接入与检查变更，复验开发入口。已获准接入的其他项目按其版本记录更新或回退。下一项真实项目采用时，由标准维护者复核分发方式；发现重复复制维护问题或需要独立发布时再评估外部仓库。
