# 明镜智能体 · 完整产品工程验证与技术选型

> **历史资料（2026-11-23 对应评审与实验）。** 下文保留当时的裁决、契约和证据，不再作为新路线的实施指令。现行架构、未决事项及阶段门禁以[当前架构与实施门禁](current-architecture-baseline.md)为准。

## 独立终裁

**调整指定组件后，采纳路线 B 为明镜完整产品开发基线。** 采用 **Python 宿主、PostgreSQL 产品账、Temporal 持久调度、Pydantic AI 动态决策**。确定性业务可从 API 直接进入受控业务服务。需要动态推理或长时间运行的任务才进入相应引擎。

两处调整已经通过隔离实测，属于今后实现必须保留的职责。其一，模型出口按产品操作和逻辑轮次持久登记唯一派发资格，同时保留未知费用，复入先核原记录。其二，Agent 的外部工具使用产品操作账与原调用/消息检查点，在工具状态未知时由工作流持久等待，可信回执到达后重新核权，原会话只继续一次。PostgreSQL、Temporal 和 Pydantic AI 均需配合产品治理才能满足这些语义。

终裁读的是[完整验收表](../requirements/whole-product-acceptance-results.md)。23 组对应 6 条路线，76 个原编号逐组无缺项、无重复，其中 **10 项有架构机制实测、45 项有局部实测、13 项指定场景尚未实测、7 项选型约束经文档核实、1 项按启用条件验证**。这些数描述证据类型。项目将以矩阵所列截止阶段和实际业务端点验收目标产品。关键质量负例、真实模型未完成业务条件、授权的单域范围、能力接入和资料治理，与恢复、预算一起参与裁决。

独立总评审者对[固定稿 8a26591](https://github.com/zhuquanwei111/mingjing---agent/commit/8a26591b1bc989f850e6a81ac9836b52a35424ae) 和两次实际 CI 的原始记录复核，确认此前暂缓的两个缺口都已关闭。另一个独立评审者直接核原件和冻结表，复核了 A/B 对照的对称性、五个授权观察点、W0a 正式交付前的故障要求及 AC-17 的原意。设计者接受修订。全表未发现仍需在当前架构阶段新增隔离实验才能作决定的硬性失败。[第一轮暂缓记录](https://github.com/zhuquanwei111/mingjing---agent/pull/14#issuecomment-7104081369) · [两项修正及原始证据](https://github.com/zhuquanwei111/mingjing---agent/blob/300868efab379fa53ef0c49065b5cb6de36594ac/lab/product-review/round-gate/RESULT.md)

**正式 W0 实施与 MVP 继续暂停。** W0a 的真实身份/业务 ACL、唯一启动与交付收据是宿主、网关和交付组件的去留条件。W0b 的真实宿主跨版本恢复及受限载荷控制决定 Agent 适配与版本路由。知识撤回、能力盲接、真实账单和混合负载各按主表指定阶段验收。即使本轮选定 B，任何必要出口无法满足实际权限或交付合同，仍要封闭该路径并重审相应组件。

**从受理到交付的协议。** 产品事务写入 Task/Run 和唯一启动意图，调度器用稳定运行标识受理，重复或启动回执丢失时按原标识核查、补绑定。正式提交和交付分别使用业务操作号与交付号，经业务/交付方核权、去重并返回可查最终收据；未知维持待核，不能把重发作为查单，也不能把上游已生效改成失败。某收端没有可核查事实且不能安全去重，封闭该正式出口或仅给受控草稿。现有 #12 在交付 POST 后才记产品已交付；接收后回执丢失的窗口未验证。W0a 首条可正式交付的受控链前必须注入该故障及上游已成、下游失败；若这一出口是产品必需且协议无法成立，调整宿主交付协议或受信接收方后重审。

## 设计者建议

首选**经调整的路线 B**。把 Python 应用嵌入明镜的任务体系，PostgreSQL 保存产品任务、操作、共享预算和交付事实；普通程序可在业务端直接完成。需要跨进程、跨时间恢复的任务由 Temporal 调度，需要动态工具决策的环节才使用 Pydantic AI。对所有副作用增加可恢复的产品操作记录，对需要续接的 Agent 工具按原调用保存受控检查点，外发经可治理的实际出口处理。上述调整改变了原先把整段 Agent Loop 交给一个重试 Activity 的做法。

业务写入的事实权威归业务方，交付由接收方确认，质量判定归相应业务验证器。明镜维护宿主身份与动作映射、启动意图、工具/模型派发、未知费用保留、查询核销和质量后交付。这些职责可以作为后续各能力的公共设计依据。宿主可按明确替换条件换成成熟应用，Agent 与调度可各自替换。当前候选中，B 提供同一套固定栈内的持久调度、受控引擎载荷、原生延迟工具和对账样本；适合明镜自有身份、业务服务和 App 交付的设计。代价是维护轮次检查点以及一个独立调度服务。没有总成本或吞吐量的实测排名。

**最接近的替代是 Agno AgentOS。** 若 App 需要直接复用一套 Agent API、会话、队列和运行（包括中断后按原 requirement 续接），它能减掉一部分 Python 宿主。真实用户、业务端 ACL 与交付依旧要整合，且受控参数转换、账本、撤权和模型出口仍由明镜承担。Windmill 在直接复用脚本、工作流和管理界面时更有价值；DBOS 在可接受稳定执行器或具备失联判定时可替换 Temporal；Mastra 是已有 TypeScript 后端时可以直接比较的 Agent/工作流一体路径。各路线均允许同样的受控引用、幂等账和网关改造。业务后端技术栈、实际需要的管理界面及目标运行资源尚无足够输入，首选的理由不包含臆测的人天或对旧开发的偏好。

## 后续功能怎样使用这套基础

开发者接入新能力时，请按本文的[接入指南、测试入口与 AC-17 验收办法](#capability-onboarding)准备交付物。

| 能力的执行方式 | 首选入口与终局 |
| --- | --- |
| App 同步查询或普通程序 | 宿主用当前用户身份调用获准服务。权威数据返回并通过该业务的完成条件即可交回；无需模型。 |
| 步骤已知、需要跨进程等待的任务 | 宿主建立任务及启动意图，Temporal 安排工作流与活动。每次有外部效果的尝试关联稳定操作号，恢复先核对业务方。 |
| 必须动态决定下一步的任务 | Pydantic AI 选择工具，公共出口按本轮授权、额度和副作用属性派发。中断后按原调用号核查结果，通过业务质量门槛后交付。 |
| 外部服务或异步执行器 | 注册能力声明所需权限、计量、取消语义、可核查回执和交付条件。同步 API、工作流和 Agent 都能复用该契约；供方无法确认终局时保留待核。 |

身份和授权由明镜 App 及资源所有方共同落实。若启用 RAG，知识检索与业务数据库均按各自权威和可访问范围供数；知识撤回、模型业务效果、第三方执行器隔离分别在首次启用前验收。父任务共享预算，业务验证器和真实交付端负责判定完成。四种执行方式共享相同的产品约束，可按负载独立安排进程与资源。

## 跨路线实测结果

五条工程都使用了真实 PostgreSQL 运行组件，按实际收端的持久记录核对合成操作。Windmill 的产品/见证实验账及 Mastra 的独立见证使用 SQLite；DBOS 的产品与引擎在同一 PG 实例分库分角色，另设见证实例。已知结果具备授权时，五条治理路径均得到同一笔业务效果、同一笔工具模拟费和一次交付。下表五个数依次为**工具请求实际到达／效果／每次到达的工具模拟收费／模型请求实际到达／下游交付**。取消、权限、模型计费、队列数据和故障粒度分别解释，不能将五种工程视为执行了全部 76 项。

## 哪些结果会改变选择

先列可能改变核心的四件事。第一项异步样本以及进程失效、受控引用等可隔离的部分已在本轮实测；涉及实际身份方、业务端提交和目标部署的结论分别归到下列明确阶段。需求全表逐组列有局部影响和最迟时点。[23 组 / 76 个原编号的逐组复审](whole-product-review.md) · [其他成熟方案、原始来源及入围标准](whole-product-alternatives.md)

1. **能力能否独立接入。** 同步型由 #5 验证三入口；可延迟、能产生副作用的外部工具由 #12 验一入口、#17 验三入口。两者都显示需要明确操作标识、权限、预算、是否可核查、版本及结果。W0 首次将目标宿主三个入口接入同一异步能力。基础链路稳定后冻结公共代码，再登记真正事先未知的实现，依 AC-17 复核。若特定实现需改数据转换，归能力适配；如果每种实现必须改公共派发或循环，调整能力契约，优先比较 AgentOS 原生 external execution。未来新增业务类型继续采用同一判据。
2. **动态回合、模型重试和升级。** 五条路线各有独立重启、配对、收据、计费证据；完整状态迁移、模型费用不确定时的安全后续和下一次正式交付中断，均不能从这一个故障窗口外推。在 W0b 由目标 Agent 宿主验证申请、挂起、继续、取消与版本排空。在途结果变可查后如何继续决定轮次适配的保留；若受治理适配仍不安全，换 Agent/网关，调度器按自身证据单独判断。
3. **真实身份、受理与正式出口。** 已实测单一授权域发送的先后、业务服务同库终核及模拟对账。实际 App 身份源、真实业务 ACL 和可观察的交付端尚缺首条贯通。W0a 测动作发生前一刻的授权和操作号；只有产品状态而没有收端事实的条件不得关闭。不同业务是否能提供独立查询/去重决定各自可启用的操作。
4. **常驻服务与成熟应用替代。** 嵌入式调度可少一项服务，完整应用可少开发运行 API、控制台或暂停队列，同时改变数据可见域和运维责任。若宿主只允许 PG 且有可靠接管，按 #15 同题选择 DBOS；若已有 AgentOS/TypeScript/Windmill 宿主或目标部署要求复用其能力，拿目标宿主在相同端点重验上表，并确认授权、发行许可及在途迁移。无此条件时不同时引入多个引擎。

## 开发者指南：给明镜接入一项新能力

**适用对象**是第一次给明镜接能力的开发者。先按下面的契约交付一个能力包，再让宿主从适当入口调用它。读者可以从受控的文本处理或外部服务入手，无须了解首期业务的代码。

**接口状态。** 本节细化路线 B 的开发设计。当前可复现的是仓库 P2 的 SDK、HTTP 接口和隔离实验。路线 B 的正式宿主尚无可提供的地址、认证配置或 SDK 版本。接线前由宿主维护者提供构建号、隔离环境、凭据开通方式、发布入口、调用／查单入口和证据访问方式，下文的逻辑操作要映射到该构建的真实接口。

### 交付物与最小契约

开发者提交 **版本化能力说明与 Schema、处理函数或适配器、业务完成规则、契约测试及运行说明**。外部依赖另附适用环境、所需权限、凭据引用和负责查单的人。无需自建产品任务账、模型代理、预算服务或交付系统。

| 能力包要说明什么 | 交给哪一方、怎样使用 |
| --- | --- |
| 身份与实现 | 维护者给出稳定的 `capability_id`、不可变版本、用途、什么输入适用、所属四类实现、受信实现引用及构建版本。目录固定契约摘要，发布者按环境激活。换规则或行为时出新版本，不能以同版覆盖。 |
| 输入、输出、错误 | 给出版本化 JSON Schema。附一个有效输入、一个错误输入、对应输出及可机读错误。列明必填字段、单位与边界。结果可含受控产物引用、来源及版本。宿主校验输入和适配器输出，业务验证器判断内容能否使用。 |
| 当前主体和动作 | 声明所需对象范围和动作。执行、读取任务、兑换产物、取消、对账可分别授权，确需审批时另声明。宿主提供已验证的上下文和关联号；资源方在真实读写处最终核权，外发方在送模型／工具前核处理权。输入中的身份字段不授予权限。 |
| 效果与完成 | 声明只读、准备草稿或正式写入，是否同步返回，谁能证明业务完成、质量合格、已收件。纯查询可当次返回；只有任务要求持久交付时，才以独立交付号取得收件收据。声明超时、可重试条件、所需限额或费用上界；无消耗也明确说明。 |
| 异步和有副作用时补充 | 声明稳定操作号的作用域及保留期、同号同载荷去重保证、可查终局及来源、回调鉴别、取消语义和历史版本兼容期。写明哪些错误能证明“未受理”，哪些只能判为未知。有副作用的同步 API 同样执行这些防重和查证约束。 |

**现成类型的对照。** P2 的 `Capability`、`CapabilityContext`、`Handler`、`ExternalPort`、`Result`、`ProviderReceipt` 可直接查签名。`Capability.description()` 和 `fingerprint` 演示如何从类型生成目录说明和摘要。P2 将内部处理统一标成 `internal_transaction`，外部协议只有 `send(data, context)` 与 `lookup(operation_id)`。路线 B 必须另声明实际读写、异步受理、取消、来源与校验语义；不能从 P2 的枚举自动推断这些保证。[P2 类型与协议](../../core/src/mingjing/contracts.py) · [原契约与生命周期](../../mingjing-codex-engineering-v1/04_CAPABILITY_CONTRACT.md)

### 四种实现怎样接

实现类型决定能力内部怎样执行。调用入口决定这次由谁发起。一个外部能力可供直接 API、固定工作流和 Agent 共用同一版本、资源授权和操作账。

| 实现类型 | 开发者新增、接哪个接口 | 复用的公共机制 | 何时才评审公共核心修改 |
| --- | --- | --- | --- |
| 普通程序或业务 API | 提供类型化处理函数或受控 API 客户端，声明只读／写入和返回条件。P2 可参照 `Handler(data, context, notes) → Result` 与 `normalize_text`；`NotesPort` 是合成样例的业务依赖。 | 直接受理、验参、授权、结果校验、产物与审计。确定性业务可以零模型调用，短请求可零工作流启动。P2 的 Handler 在本地产品事务内执行，适合纯计算或同库受控写。会改变远程状态的同步 API 在 P2 也须走 `Kind.EXTERNAL` 和 `ExternalPort.send/lookup`，该样例契约还要求已知正数成本上界（`budget > 0`）。正式接入按实际资源计量，沿用正式出口约束；本地事务可重试，不能在 Handler 里直接发远程写。 | 新字段、业务规则或一种服务地址只改能力包。若网关无法表达所需对象动作或一种新的效果边界，再带失败用例复审。 |
| 确定性工作流 | 提供版本化工作流定义、分支、依赖、等待／取消点与适用的 Activity。外部 I/O 放在活动中的受控能力调用，工作流历史只传不透明引用。 | PG 任务、运行和操作账，Temporal 启动、等待、恢复、必要的子任务与预算。以固定 Workflow ID 核对启动；活动重试沿用同一业务操作号。 | 新流程和新队列配置通常只改定义／适配。现有等待、通知或取消模型无法表达必须的执行语义时，才改公共调度契约。 |
| 动态 Agent | 提供目标、允许的工具契约、版本化提示词、输出验证与停止条件。在 Pydantic AI 中发起按轮推理，工具请求交公共网关。保留原调用 ID 与消息引用，声明无进展、步数和预算限制。 | 按操作及轮次唯一认领模型派发资格，检查当前权限与预算。工具未知则由 Temporal 持久等待，可信结果与原调用配对，重核后原会话至多续一次。 | 新工具或提示词留在能力包。若新协议无法完整表达消息配对或安全恢复，先改 Agent 适配器；只有共同状态或派发保证不足才复审核心。 |
| 外部异步服务 | 提供提交、按原号查询、状态映射，按供方实际能力提供已鉴别的回调和取消适配。附供方状态样本、收据及冲突规则。P2 的 `FakeProvider` 可复用作故障夹具。 | 先登记操作与预算，再发送。PG 留受理／未知／终局，Temporal 等待；归一化回执后核销并唤醒原任务。公共层负责去重和关联，供方负责证明效果。 | 供方换状态名、签发方式或端点只改适配器。供方缺乏安全去重或权威查证时限制该能力；不能通过改公共账把未知宣告成功。 |

### 从安装到停用

1. **定义并安装。** 先写完成条件与权威收端，再写 Schema 和处理器。在隔离环境加载受信实现，让目录拿到版本、清单和摘要。P2 已有 `builtins(db)` 安装清单，`service()` 用清单构建 `Catalog`。把新能力列入装配清单要在差异中记录，业务开发者无需修改网关的分支判断。[四类示例](../../core/src/mingjing/examples.py) · [P2 装配入口](../../core/src/mingjing/__main__.py)
2. **登记和验证。** 发布者登记指定版本，仍不可发现为可执行项。运行正负契约用例，校验 Schema、返回、错误、效果、去重、资源权限和版本兼容。异步写另外检查收端和丢回执。通过后登记验证结果与对应构建。
3. **发布和授权。** 发布者在指定环境激活已验证版本。资源管理员另按租户、主体、对象、版本和动作授予权限。已发布但未授权，应发现不到、调用不到；仅登记或已停用也一样。执行权本身不授予收据内容和产物读权。
4. **发现和调用。** 宿主先按当前主体、环境、发布版本、目标、输入输出筛选，再将相关且获准的候选交调用者。直接 API 带客户请求键提交；固定工作流在 Activity 调同一能力；Agent 只提出已提供的工具名和参数，由网关解析能力和版本，验证参数、当前分项目标、预算、权限与效果。实际执行端独立核权，正式写前核业务质量。前两个入口不为选择已知动作调用模型。
5. **回传和追踪。** 同步结果通过 Schema 和适用的质量校验后返回；异步先返回 Task／Run 或受理引用，再按下表查询。开发者区分参数错误、权限拒绝、明确未受理、在途、未知及执行终局。返回机器可读的类别、可安全展示的原因、操作引用及允许的下一步。宿主按 Task → Run → 操作／尝试串联 Trace、版本、授权决定与权威收据。日志及引擎历史只留必要引用。操作号跨重试稳定，尝试号逐次改变。
6. **升级和停用。** 在隔离环境并行装载新旧版本；先验新输入、旧任务恢复、停接和回退，再将新流量切到新版本。废弃时停止新受理，在途按原契约且仍有权才可继续；紧急禁用拦住尚未交接的新动作。保留只读对账和既有收据的受控访问。不兼容的在途任务留给旧 Worker 或隔离待核，回退也不恢复旧授权。[版本与停用样例](../../core/VERSIONING.md)

**路线 B 接线时索取的逻辑接口。** 下列是宿主和能力方要落实的输入输出，实际方法名、URL 与鉴权方式由目标构建提供。

| 调用方 → 接收方 | 最小交换内容 |
| --- | --- |
| 客户端／任务路由 → 平台目录、调用网关 | 发现传任务目的、对象与所需输入输出；调用传能力 ID、固定版本、对象、输入与客户键。宿主从调用会话或受托任务验证主体与用途，生成 Task、Run 和操作号，不能仅凭 Task ID 扩权。 |
| 平台网关 → 能力实现 | 传已校验输入、可信上下文、稳定操作号、本次尝试号及限额。开发者返回类型化结果／产物引用，或受理引用与待查状态。已授权的读取方按平台返回的 Task／Run 查进度与可继续入口。 |
| 对账器 ↔ 业务方／异步适配器 | 平台持独立只读授权，用原操作号查询。适配器向平台交回来源、原号、对象、结果版本及权威状态。回调是唤醒线索；能证明终局的回执可直接核验，否则须回查。取消按原操作发往实际执行方并取得接受或停止的独立确认。 |

### 外部提交和结果确认

| 实际观察 | 适配器交回什么 | 平台及调用者如何处理 |
| --- | --- | --- |
| 供方仅确认受理，或明确在途 | 原操作号、供方引用、状态与可查入口 | 保存受理，返回等待状态。HTTP 202、排队成功或工具调用结束均不能解锁依赖业务完成的后继。 |
| 已生效／确定未生效 | 经过验证的终局、业务对象及版本、匹配操作号的权威收据或明确未受理证明 | 绑定租户、能力版本、对象与原载荷摘要，只核销一次。业务方证明效果，产品按任务条件决定成功或部分完成。 |
| 超时、断线、查无结果或回执丢失 | 未知及原号；区分查询接口暂不可用和能证明未受理 | 保留预算，只读查原号或等可信回执。只有权威方证明原请求此前从未受理、也不可能迟到受理，而且同号去重仍有效、当前授权仍在、载荷相同，才允许同号重试。不换号重做。 |
| 回调重复、乱序、错配，或任务已取消／撤权 | 验签或等价鉴别发送方，校验租户／操作／对象与结果版本；疑义按原号回查 | 拒绝错绑，已确认终局不因旧通知倒退。PG 在同一事务核销并记可重放的待唤醒项。取消或撤权后，只用另有授权的对账主体处理旧效果及费用，禁止新的模型、子任务或交付。 |
| 调用方取消 | 声明支持程度。可取消则以原操作为目标，用获准的幂等取消请求传到实际执行方并取确认 | 区分已请求、已确停、不可取消、已生效和待核。补偿或反向操作若适用，需要新的权限与操作号。 |

**正式写入的准入线。** 供方须能按同号安全去重并提供事后可独立核实的权威终局。回调可选，有可信查单可轮询；单靠可能丢失的一次通知不足以开放正式写。缺任一保证时，仅开放经授权且已验证的只读查询、本地预览或不触达供方的草稿。已合法派发才遇到不确定性，则保留待核并锁住依赖项。业务已成但收件回执未知时显示“业务已成／交付待核”，收件方按**交付号**核实。[W0 宿主契约](https://github.com/zhuquanwei111/mingjing---agent/blob/8095d6f79e2e4e42fbdef03c8fdbfdf6b4785b35/docs/designs/w0-host-design.md) · [已知与未知的隔离运行证据](https://github.com/zhuquanwei111/mingjing---agent/blob/300868efab379fa53ef0c49065b5cb6de36594ac/lab/product-review/round-gate/RESULT.md)

| 现有 P2 调用 | 在合成数据上应观察到 |
| --- | --- |

### AC-17：基础链路稳定后的独立盲接

1. **先封存，再选题。** 基础链路通过其准入后，记录未改动的基线 SHA、构建/依赖、环境、能力清单、接入说明与整个公共核心的路径/指纹。标明注册装配、能力私有目录与核心边界。不要预先指定能力名称、Schema 或特殊分支。
2. **由未参与该能力或首期实现的开发者选一个中立能力。** 独立接入者只从文档、公开契约、样例与测试入口出发，选一个在基线中未被专门适配、能暴露现有样例未涵盖语义的能力。测试方另给无权、故障或乱序输入。将提问、缺失接口和临时协助记录在案。
3. **按同一机制完成一次可查的从发布到停用。** 至少通过两种适用入口复用同一版本；另一个入口如果适用也实测。确定性入口验证模型零调用；动态入口检查真实工具选择和配对。核对真实收端、结果与授权负例，写入能力另查操作、去重、未知和取消。不能用预设三类样例的重跑抵数。
4. **逐文件判读差异。** 保存前后 SHA、完整 diff、每个公共文件是否改变及原因。区分业务包、安装清单／配置、公共契约、网关／调度／状态。报告包含实际改动、触发用例、可复用性、回归结果与证据位置。零处也附对比。仅业务适配或声明配置即可完成且语义全过，支持标准接入；必须改公共契约时记录受影响范围并复审。靠特判、放宽授权、隐藏失败或跳过查单跑通的，不通过。当前 AC-17 仍未实测。
