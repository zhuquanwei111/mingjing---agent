# 明镜全机构知识库五层技术选型方案

**供架构与选型评审，也可直接交给调研智能体。** 需求已确认。请按下列五层分别寻找能完成明镜任务的候选，可以是一项现有能力、一种产品、一套组件或一项模型服务。调研由项目方安排；回件由主会话统一核对，提出逐层选用及整套组合的结论。目前五层的产品、模型和组合均待选。[确认的需求版本](https://github.com/zhuquanwei111/mingjing---agent/blob/43b6f2384bd8d9afc54ec0f0bda26fb9117a1d25/docs/requirements/knowledge-base-requirements.md) · [知识库架构方案](knowledge-base-architecture.md)

## 可随任一层任务一起转交的背景

- 明镜服务一家内容与主播经纪机构。七个范围是制度与岗位协作、主播经纪与人才培养、内容创作与素材、直播与制作运营、商务客户与项目交付、经营财务与合规、行业研究与组织经验。已有材料较少。前期记录中的约 300 人是潜在使用人数；并发、文件数量、视频时长、增量、上线日期和经费仍须从业务取得。
- 用**同一条片尾**想清楚候选服务谁。编导交商务，商务可给原客户约定的版本，也可凭独立教学许可交给带教。带教给指定新人班发教学片。原件换剪，教案由本课负责人改；撤教学版，学员重开旧链接只见停用提示，其他客户看不到项目标题。若两种用途均被撤回，客户版也须停用。曾经送达和客户确认分别核实。
- 另一类任务是查事实。跨页结算表须读对单位和扣项；字幕说“切近点”须回画面才能证明真的切镜；“明天下午谁有空”须由排班方提供当前事实。明镜原有任务、授权、模型出口和交付契约继续适用。资料可以按编号直接定位，只有需要时才做语义查找或生成。现有 4 核、8 GiB 云机仅供临时开发。报告分别给出适宜试验条件、实际测量条件及生产仍缺的输入。

## 什么样的候选值得报告

1. **对得上明镜的一种任务。** 写明负责哪一层、输入和产出、谁能据此完成什么事，以及它替代现有办法的哪一步。保留能办成事的简单对照。成套产品按同版的实际覆盖逐层列出；专用组件可以只负责一种格式或一个环节。
2. **能核查且能接入。** 给出准确的产品／模型、版次或修订、维护主体、官方说明或模型卡、接口或样例、适用许可及费用来源。区分社区版、商业版、自托管与托管服务。说明数据和日志送到哪里、需哪些身份和依赖、输出能否带版本和原件定位、如何导出与替换。自有业务资料仅按实际授权使用。
3. **说清边界与代价。** 逐项区分原生能力、用公开接口可补的部分、须另建或买的部分、尚无证据的部分。写明谁承担适配和日常维护、失败后如何恢复。受限资料如有绕开核权的入口，具体指出入口和影响范围。无对应正式能力的路径不能因总体得分高而入选。
4. **留下可复核的依据。** 标出“官方文档声明”“第三方或具名使用方实测”“明镜隔离同题实测”“真实岗位／收件端证据”，注明日期、环境、版本和局限。没有运行过就写未测并给出区分候选的验证办法。厂商榜单、通用中文排名、截图或开发机能否安装，单独都不足以决定采用。调研阶段可只交文献与验证设计。

## 五项调研任务

每项可单独分发，附上上述背景、已确认需求和文末回件格式。下面的用例是候选比较题，待业务决定的 MVP 指标另订。

### 一　资料原件、版本和发布

**要选什么。** 比较沿用业务文档平台管理原件与发布、把获准托管资料登记到受控版本库这两种办法。输入是原件、来源、对象／项目、业务许可和发布决定；产出是稳定资料号、不可混淆的版本、适用日期、用途限制、原件位置与衍生引用关系。合同与出镜许可的决定仍来自各自负责人。

**入围与对照。** 说明同名项目如何区分、谁可发布或撤回、能否回看当时采用的条款、换岗如何转派教案的修订责任。给出版本、权限变更、按版本读和导出所用的实际接口或可行适配点。对照人工维护版本清单、在原平台按身份打开原件。

**交回的证据。** 用两次修订、两个客户、两份用途许可对照。先撤教学许可，再恢复学员读权；单独比较覆盖全部用途的撤回。说明旧群链接、旧回答和收件处各会返回什么，谁负责更新教案。报一次更新／撤回需要几步、备份恢复前怎样查最新禁用状态，列仍需其他层配合的出口。

### 二　检索服务

**要选什么。** 比较原平台搜索、精确编号与关键词基线、可组合的全文／向量混合检索、成套检索服务。输入是可信身份、用途、项目、问句或编号和已发布资料；产出是排序后的授权引用、原版原位和缺证说明。语义模型怎样表示问题归第五层，本层负责索引、过滤、排序接入和更新。

**入围与对照。** 候选应能限定机构、项目、版本及用途，支持增量更新、撤回和重建。说明过滤在哪一步做、排序与缓存是否暴露受限标题、旧数据尚在索引时谁挡住新取用。检索器只返回限定范围的引用也可入围，须说明由谁终核。与同一批资料的按号／按词查对照。

**交回的证据。** 用同名的两个客户、一个旧授权和“蓝尾巴”的口语改写。逐题记录前列结果、必须找到的证据排第几、误入的是哪一版；同时记录无权者实际可见内容。另列改一份资料与重建时的可用性、耗时和维护工作。只展示最终回答无法判断检索优劣。

### 三　文档与复杂版面

**要选什么。** 比较原生读取工作表和文档、版面解析、扫描识别及需要时的人工复核。输入是有固定版本的 PDF、表格、幻灯片或扫描件；产出是保留表头、行列、单位、脚注和阅读顺序的内容，附版本与页区／工作表单元格／幻灯片位置。

**入围与对照。** 说明支持哪些格式、何时直接取原生数据、何时需识别或人工核对。能从提取结果打开原位置，遇到合并单元格、跨页表头或识别不清能标出疑处。对照员工手工打开同一页或读取原生工作表。

**交回的证据。** 对同一项目跨页合同、补充单和对账表，核对“3.6 万元、扣项 3,000 元、实收 33,000 元”的各自表头、行列和出处，再用相邻项目作反例。记录错列、漏脚注、错单位的位置、需人工返工的页数与处理成本；若某格式失败，可只申报已证明的格式。

### 四　音视频与图片

**要选什么。** 比较已有字幕和审片标注、带时段的语音转写、画面或图片定位、人工校正，以及它们的组合。输入是原片／剪辑版、定妆图、可用时段与许可；产出是可回放的特定版本与时间范围或图片位置，标明依据来自声音、画面还是人工观察。

**入围与对照。** 说明支持的媒体和中文语音条件、时间点对哪一版、限制片段怎样裁切、封面与转写怎样继承用途授权。只能转写的候选可作为部件，须把“只有字幕时画面待核”的结果交给下一层。对照字幕检索和人工看审片记录。

**交回的证据。** 用台词相同但切镜相差数秒的粗剪／定稿，加一张定妆图。分别问“说切近点在哪秒”“手什么时候真的出现”“这套去掉哪个头饰”。报实际打开的版本与时点／图中位置、定位误差、人工校正时长、每小时媒体的处理开销。教学许可有效时同一学员应能课内播放、不能下载原件，链接转给班外员工后仍无法打开；若依赖外部播放器或宿主执行，指明由哪个出口拦截。说明撤回后谁挡住片段、封面、转写和旧回答。

### 五　中文向量与回答

**要选什么。** 分别比较中文嵌入模型（按意思找）、可选重排模型（重排候选）和受控回答模型（根据原件解释）。一份回件可只涉及其中一个角色。输入是员工原话、获准的上下文与证据引用；分别产出向量及其模型版、排序结果，或带可打开出处的答案、澄清问题、缺证说明。

**入围与对照。** 说明是否理解岗位俗称、同名、改口和跨轮“那版”的指代。给出权重或服务版次、许可、中文适用条件、推理与数据出站条件。保留纯关键词和直接展示获准原文两种基线。对比嵌入固定语料与检索设置，比较重排固定候选集，比较回答固定同一批证据。

**交回的证据。** 用“那个蓝尾巴能投吗”再改口换客户，及“少了三千”但缺最新流水。分别列没找到、找错版本、找对却答错、合理追问或应当答不了的题。核对送给模型的片段与最终展示内容，统计每百问成本、等待时间、人工返工；换向量模型需说明如何按版本重建及回退。只有公开榜单时注明明镜口语仍待测。

## 如何统一回件并选出组合

**每个候选交一张可独立读懂的记录。** 跨层候选可共用一份部署和成本说明。请保留失败例，原始证据给链接或可核对的受控编号。

| 回件字段 | 填写要点 |
| --- | --- |
| 身份与适用范围 | 层与子任务、候选名、准确版本／服务版次、形态、可覆盖的资料和岗位任务、直接对照对象。 |
| 能力与出处 | 每条关键能力的原始链接、核查日期、证据类别；哪些原生、需适配、另购、缺失或未知。依赖相邻层时给出一份示例输入与输出。 |
| 许可与运行 | 代码／模型／服务条款，商业使用与数据出口条件；硬件、存储、网络、运维角色；标价、试算、实际费用分列。不能转出受控资料时说明可用路径。 |
| 验证与反例 | 样本来源及版本、身份／用途、对照、控制变量、预期与实际、分子／分母、失败和未测项。注明表中哪题区分了两个候选、补什么证据可能推翻结论。 |
| 接入与退出 | 权威源和版本如何传递，已知失效窗口，撤回／重开、导出／重建／迁移步骤，人员工时及未覆盖风险。可建议进入同题验证、限用途再看或排除，并给理由。 |

**主会话如何裁决。**

1. 固定需求版本及同题材料。把回件按“五层 × 岗位任务 × 适用范围”并列，一项能力标清谁实现、证据在哪。文档声明支持的候选可进入验证；缺少版本、出口或对照的回件，先列最小补证项。不同机器、样本、语料、模型端点的数字保留原条件，不直接排名。
2. 先看影响使用资格的结果。跨客户泄露、撤回内容重现、受限内容送到未获准的处理方、错把金额或过期许可说成当前可执行事实，都使相应用途无法入选。局部组件可由另一层补齐，但须指出具体出口并用整套组合复验。未经验证的关键项留为待证。
3. 对满足同一用途的路线，先比员工是否办成、能否按原版原位举证，再比返工、运维时间、等待、迁移及成本。分开列初次整理、日常新增、修订／撤回、每千页／每小时媒体／每百问等实际口径。相同效果下优先复用现有流程、减少维护；资料量和业务量未知时给带假设的区间或改选条件。
4. 核整套接口。第一层的资料号、原件版本、许可和撤回状态贯穿三／四层的定位及二层的索引；第五层的嵌入版本要与索引一致，回答引用要能回到第一层并按当前用途重开。成套引擎自带的解析或模型只计一次成本。让同一条片尾走完交接、换版、撤回和收件重开。用收件回执丢失的例子分别按业务操作号核业务终局、按本人交付号核送达，检查同一份材料没有重复交付。把撤回分别放在首次不可撤销交接之前、之后，核实际收端及可证明的先后；顺序无法核实时，受限用途留待验证。
5. 主会话在本 PR 交回逐层及整体决定，列**推荐组合、可替代组合、为何选／舍、证据位置、尚未验证的边界、何时改选**。证据只能支持某种格式或用途时写明限用，关键差异尚无同题证据时说明需验证什么。架构与选型评审完成后，再由项目方决定 MVP 的岗位、功能和验收标准，获准后才搭建。

已有[岗位原话样题](../requirements/knowledge-base-conversations.md)可用来理解题意；公开校准题不计入岗位盲测成绩。[已有隔离证据](../requirements/knowledge-base-evaluation.md)注明了每次测了什么。之前的关键词对照只覆盖少量合成资料，旧读权恢复后能否打开撤回内容仍要按新组合实证。下列既有产品线索保留出处与当时的假设，调研者可增删候选。

### 为什么要能回源、查词、按意思查

“把上周五晴禾签回来的那单打开”通常可以按项目和编号取原件。“片尾一黑就掉人，还有哪几个组也是这样”需要按意思检索多个版本，并检查画面与时段。“明天下午哪个化妆师还有空”必须查实时排班。检索服务可以解释排班办法、协助识别项目，知识库中的历史排班表不能证明此刻有空。系统能回答“行业里有人这样做过”，并不意味着项目方已经批准把它写成制度。

## 业务材料从哪里来

设计覆盖机构制度与协作、主播经纪与培养、内容与素材、直播与制作、商务与交付、经营财务与合规、行业研究与组织经验。约 300 名潜在用户是规模背景，实际岗位、场次、资料量及负载有待采样。资料按原件、授权对象、项目、版本、生效时间和衍生引用关联，同一知识可供多个岗位使用。

公开参照覆盖近 300 人的内容制作团队、多地达人经纪团队、百人级商单团队和一次大促的资料样本。团队人数、达人资源、每月商单和每场材料分别计量。[四个同行的资料及可比范围](knowledge-base-materials.md)

| 检索服务 | 原方案比较 RAGFlow 与 Docling＋pgvector＋明镜发布授权。本稿另提议在同题中试 WeKnora v0.9.0 标准 Compose，以独立 ParadeDB（PG 17、pg_search、pgvector）和 Redis 承载知识检索及入库。已有文档平台按用户身份搜索、纯关键词检索作为基线。三条路线分别跑，可复用相同输入和判卷，无需常驻三套引擎。 | 精确编号、口语改写、同名项目、时效冲突以及重开引用都要评。记录建库、改一份资料、撤回和故障恢复的实际步骤与工时。若无法在发模型和交付前按对象重新核权，则关闭该候选的受限路径。 |
| 文档与复杂版面 | 普通文档先试原生解析；复杂 PDF 同题试 MinerU、Docling；原生 XLSX 比较直接读取工作表和单元格（openpyxl）与引擎解析。对跨章节图文缺失可加试 Ontos-AI Knowhere。 | 表头跨页、金额单位换列、脚注例外、页码、单元格、幻灯片图注分别核验。保存从解析片段回到原件的定位。转成 Markdown 后仍须查得原位置。 |
| 音视频与图片 | 候选为 FFmpeg 提取片段与帧、faster-whisper 做带时段的转写，再关联原片和人工标注。与直接查已有字幕、审片记录的路径同题比较。 | 区分“口头说切镜”与“画面何时切镜”，核时间码、画面版本、可用片段边界及二次使用权。纯字幕不能证明画面时应明确缺证。 |
| 中文向量与回答 | 比较关键词、BGE-small-zh-v1.5 向量及两者混合；其余条件固定后再测重排的增益。生成经获准的明镜模型出口，Qwen3-8B 可作隔离候选。分别评价找资料、读对资料、用员工听得懂的话回答。 | 同批用户原话、同一权限和资料版本下，分开报告遗漏、挑错版本、答非所问、过度追问、编造及成本。模型端点及预算未确定时只报告检索结果。 |

## 哪些路线值得优先试，什么结果会改变顺序

| 路线 | 值得试的理由 | 主要代价与改选条件 |
| --- | --- | --- |
| 复用实际办公平台的搜索与原件 | 正式文档若已由业务持续维护，保留原编辑、审批和版本来源最省重复录入。 | 先确认实际平台和身份接口。若跨源题找不全、旧文档或附件权限在二次使用时无法核实，可保留原件并增加受控检索。 |
| WeKnora 成套服务 | 作者建议优先隔离试其团队部署。关键词、向量、解析队列有现成接口，便于用同一来源对比精确词和口语改写。 | 需要单独的服务、检索数据库和队列；授权粒度、原文页码／单元格和撤回时序须实测。编辑端和检索端不得提供可绕过明镜发布与授权的受限入口。 |
| RAGFlow 完整引擎 | 直接对照运营可复用的文档管理、解析、检索界面与引用能力，覆盖已有的候选路径。 | 与其他路线同测换版、引用、权限和实际运维步骤。通过相同硬项且维护更省时可以优先采用；开发机装不下须记录资源需求并在合适环境检验。 |
| Docling＋pgvector＋明镜自己管发布和权限 | 可逐层替换解析、中文模型与存储，便于保留明镜的对象关系、版本和定位信息。 | 团队要承担索引重建、发布管理、界面和回滚。若成套产品无法贯通对象权限或原件定位，可分格式采用此路；必须列出新增维护工作。 |
| Onyx 或同类企业搜索 | 若主要问题是大量分散的现有系统，要直接比较其连接器和权限同步。 | 核对所需版本、许可、同步周期。若权限变更与新请求之间存在窗口，需由实际数据源再次核权或限制相应用途。 |
| Knowhere、Obsidian 等局部组合 | 对长篇图文可比较 Knowhere 的章节关系和关联资产；写作团队可用 Obsidian 编辑 Markdown，经原有审批后发布。 | 分别测跨章节题有无改善、编辑发布是否减少重复劳动。共享笔记库的可见性须与客户、个人记录的对象权限分别核实。只有局部收益时只采用对应一层。 |

在明镜宿主与知识服务之间，候选适配须能传递当前身份与目的、项目或对象、资料号与版本、原件位置；返回足以复核的引用和已知缺口。索引是可重建的派生物。候选按获准接口取用原件；生成、受控分享与本人重开各再核权。权限源失联时停住受影响的调用，保留仍能核实的资料。标价、实际费用、运维工时分别记录。

## 如何做决定

1. 用[员工原话样题与判卷方法](../requirements/knowledge-base-conversations.md)核对题目现实性。隔离样题均为合成示例；正式盲题由岗位人员以原话提出，保留口误、俗称、纠正和后续追问。确认资料时无需一次性交付完整资料库。
2. 同题固定身份、时间、附件、原件版本和可使用的模型。先跑现有办法和纯关键词，再跑候选，单变量比较解析、检索和回答。记录各题结果及人工操作用时。不得把不同硬件、不同模型或缺失样本产生的差异直接归因于引擎。
3. 权限泄漏、将撤回资料重新交给用户、把错金额或失效使用权答成可执行事实，逐例单列，未修复的路线不得用于相应正式范围。通过硬项的候选再按岗位任务完成率、维护工时、查询等待、每千页处理成本及每百问成本比较。并发、容量、采购金额按实际岗位负载与成本测算。
4. 将逐题结果、原始出处、失败复验、剩余限制、责任人与决定记录在本专题，供项目方选择采用、限范围采用或退回重选。运行中另测并发入库与撤回、索引重建、备份恢复和同一失败运行的追查。公司级验收还需真实接口和岗位签收。当前已交付的是分类、待评候选和公开校准题；技术采用决定、独立评审和知识库实测均待取得。
