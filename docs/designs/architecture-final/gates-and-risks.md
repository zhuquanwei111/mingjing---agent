# DeerFlow 工程关口、风险及有限反转

现行依据：[架构入口](../current-architecture-baseline.md)与[需求修订](../../requirements/current-engineering-requirements.md)。本文件为现行设计，不是运行报告。

## 1. 关口分离

| 关口 | 状态/目标 | 必要交付与通过标准 |
|---|---|---|
| 主体选型 | R3 独立推荐，用户确认变更 | 选型依据可核；不把设计或上游局部报告登记为本项目运行通过 |
| 仓库基线 | [#29](https://github.com/zhuquanwei111/mingjing---agent/pull/29) 独立复审和 CI 通过后已合并 | 现行架构、规则、图、矩阵、需求、旧历史及阶段完整一致；适用静态检查/现行 CI；实际独立回执；不批准 W0 |
| H | 待做制品与开工准备 | 参考 v2.2.0 / `58fc5bd5b8e6ea46538e9481ba06ca2a46e14e2a`；确定实际可取得安全版本、commit、镜像 digest、依赖、许可证、维护/回退；处理已知 CI 失败的实际影响；真实 App 入口与身份映射、必要权限和适配边界、测试环境/预算；另获 W0 批准 |
| W0a | 待另批真实最短链路 | 使用选定真实宿主、两个测试主体、真实中立资源和独立读回，验证普通/适用固定逻辑、许可/越权、必要质量、正式效果/交付；记录真实原生与适配差异 |
| W0b | W0a 适用条件通过后另按授权接续 | 原生动态 Agent 与实际工具、同业务能力复用、适用异步；普通权限变化、合理恢复/取消/费用、真实效果与失败/未知；最终构建回归 W0a；不重跑历史 H1 当通过 |
| G | W0/旧 P1 适用判据实际通过且获准后 | 建设完整产品所有实际必要公共能力，依据现行76项记录实现/配置、真实结果/失败复测、权限/质量/运维；独立 AC17 在稳定基座后、M 前通过。条件性能力可未启用，但必要能力不能延期到 M |
| M | G 通过、业务方案独立评审且另批后 | 首期跟播→复盘→次日妆造预约及只复盘；真实正确场次、来源、前置条件、有效预约、真实回执和业务异常；分别判复盘和预约结果；首期不是完整产品上限 |
| T | 有限试用另获授权 | 按批准的岗位、资料和服务验证质量、资源权限、成本与恢复；跨期条目分别记录隔离证据和真实业务证据。 |
| P | 正式流量另行放行 | 按实际目标负载核对容量、许可、安全、真实账单、值守、回退和恢复演练，由业务方签收。约 300 名潜在用户不代表并发或生产目标。 |

W0/G 用两名测试主体和可独立读回的中立资源验公共机制，例如读取物品余量、领取一件物品、分别查看分析与领取结果。真实复盘和妆造预约留到获准的 M，使用实际业务资源重新取证。

在同一需求编号下记录适用阶段、环境、构建、用例、实际读回、失败及复测。隔离试验和真实岗位结果分别留证；条件能力暂未启用时，核实入口确已关闭，启用前另验。正式业务所需公共能力须在 G 建成。W0a 的 A1–A8、W0b 的 B1–B8 逐场景签收，各自注明适用条件并取真实收端证据；W0b 以最终构建回归 W0a。

旧 P0–P3 仍为工程阶段门禁：P0→H 只读及必要受控准备，P1→W0a/W0b 隔离 walking skeleton，P2→G 必要公共层，P3→M 及以后；旧技术执行类型 EXEC-0…3 不再是强制新架构分类。既有历史 P1/P2 CI 通过不等于当前 W0/G。

## 2. 旧 W0 场景处置（保留实质，不照搬实现）

原固定场景见[历史 W0 验收表](https://github.com/zhuquanwei111/mingjing---agent/blob/8095d6f79e2e4e42fbdef03c8fdbfdf6b4785b35/docs/designs/w0-host-acceptance.md) 及 [旧 gates-and-risks.md](https://github.com/zhuquanwei111/mingjing---agent/blob/114af05ea6a24cde7f36d3e3dce7225234aa279a/docs/designs/architecture-final/gates-and-risks.md)。下面是新验收设计方向，不是已运行/不把旧场景标绿；实际 W0 方案按真实路径和风险批准。

| 旧编号 | R3 现行通过条件 |
|---|---|
| A1 | 真实合法普通业务调用、正式结果与本人可查交付；原生入口或实际业务接口均可 |
| A2 | 可信主体、输入有效、能力可用及授权，伪造 actor/owner、无权资源真实拒绝；不要求独立全局目录 |
| A3 | 正式操作重复/受理不确定不造成重复效果；普通任务允许有限重试、重做；不强制所有 Run 统一受理账本 |
| A4 | 确有必要的确定性质量规则正负例，错误正式结果不假报完成 |
| A5 | 实际业务资源端核权，模型参数不能给自己权限；无权/不明权限拒绝 |
| A6 | 已交付/未交付及失败、部分完成准确；重要交付按实际需要查证，普通失败可提醒/重做 |
| A7 | 正式业务生效、丢回执；查权威、同意图可靠幂等重送或等待/人工，不换意图盲重做 |
| A8 | 本人及获准用户交付和新访问正确，私人历史不泄露；普通旧合法输出默认保留 |
| B1 | 原生 Agent 动态选择；至少适用的两种入口共享业务能力；不强求三入口经过同一引擎 |
| B2 | 模型响应丢失，允许有界安全重试/正确结束；实际硬资金限才验证严格准入，不要求每物理调用精确一次 |
| B3 | 工具正式效果已成结果未记时，保证不会不可接受重复；普通工作按风险重做/提示 |
| B4 | 已记状态与后续依赖正确；按原生合理恢复/补跑/结束，不要求每节点无损接管 |
| B5 | 常规权限变化按已定规则完成/暂停/提醒/停止均可，后续新无权访问及正式操作拒绝；只有明确即时要求才做相应交接竞态 |
| B6 | 原生步数/并发/时长等有界，模型/工具故障和费用合理；不兼容替代不假报 |
| B7 | 必要上下文、真实主体/结果、权限与观测可追；不追踪全部历史派生或暴露敏感日志 |
| B8 | 适用升级/停用/回退及在途处理；允许合理排空、重做、人工恢复，重要事实不丢，不强制所有代次精确迁移 |

## 3. G 的现行覆盖分组（十组是追踪索引，不是十套独立平台）

| 旧组索引 | 现行目标及必要取证（按适用业务） |
|---|---|
| V01 受理/扩展 | 中立事实查询从普通接口读回且模型调用为零，动态任务由 DeerFlow Agent 调用同一业务能力。需要的工作流、异步及调度先在 DeerFlow 原生路径验收；确认可信主体与实际结果。AC17 由未参与原接入的人接入事前未定制的能力，记录核心实际改动与原因。不要强制单一注册/调度/账本 |
| V02 执行可靠性 | 客户端断开、故障、必要任务恢复；可重做、补跑、人工/告警、适当检查点；确需无人值守才验证实际时效和持续授权，不预设原 Mastra/Temporal 双栈 |
| V03 身份/隔离 | 同机构不同员工/业务资源、实际接口/检索/文件/会话/启用外部目的地的授权；常规权限变更按确认规则；不普适双租户、五出口原子闭包和全历史遮蔽 |
| V04 正式效果/费用 | 正式业务资源幂等/查证、取消及迟到不推进后续；普通费用可配额、监控、有界重试；真正资金硬限才严格并发准入及实际费用对账 |
| V05 公共数据/对象 | 采用实际成熟处理/存储；普通资料处理可查、重要质量/发布/撤回按需；必要字节/版本/受控原件访问、真实错误处理。非强制 Hop+SeaweedFS 或独立数据平台 |
| V06 知识/解析 | 获准检索与必要来源/版本，后续撤回停止新检索/原件访问，合法普通历史保留；原生更新/范围重建；复杂文档/表格/图像/音视频与必要视觉时码按实际业务效果，不强制全 Wiki 闭包/批次总账 |
| V07 模型/上下文/质量 | 实际获准模型、兼容替换、工具配对、必要来源/裁剪；重要结果真实质量门、可复核回归，条件记忆按需；不重建独立模型/评测系统 |
| V08 管理/观测 | 实际必要的免费或已批准管理页面/API、用户可理解进度、必要审计/费用来源及可查故障；原生工程优先、不默认重复控制台 |
| V09 部署/运行 | 固定安全制品、实际配置/健康/回退、适用资源边界，真实容量指标另按 T/P 目标；不凭潜在用户推断生产能力 |
| V10 备份/恢复 | 依据已批准 RPO/RTO、损失及任务类别保护关键业务事实、必要原件及配置；适用恢复/未知核实，普通中间产物可重做，不默认高等级跨域拓扑 |

这些组索引与 `licenses.csv` 的历史 V01–V24 是两种旧编号体系，勿混淆。76 项现行映射保持 FR/NFR/TS/AC 编号，工程证据按实际实现和配置签收，业务真实例在 M/T/P 另补。不得为图表或组别数量增加服务。

## 4. H 的未决任务（不可伪造结论）

- H-V：v2.2.0 固定版实际失败后端 shard 2；完整根因尚未知。选择真实制品前核失败影响、公开安全问题、支持、发布及依赖许可/镜像 digest；有可信修复版本时重核受影响证据，不要求历史所有无关测试全绿。无安全制品/严重不可处理缺陷才阻断主体。
- H-A：明镜应用后端尚未建设。由公共基座负责必要的 App 服务端接入，确认实际账号、身份源与可信资源责任；原生 OIDC/session 优先，若后端桥接则真实服务端映射，严禁共享 internal token 给终端、默认 owner 或伪造 actor。原生授权启用/最小角色，实际资源和外发边界可验；仅在业务明确要求即时阻断时验证对应边界。
- H-B：哪些真正的后台场景需要无人值守时效；划清普通业务函数与执行管理的责任；工作流、异步任务和调度先核 DeerFlow 原生接口。仅在实测显示必要时效或正确性有缺口时评估局部接线。AgentRuns 保留 handle 不跨重启，不能假称自动恢复。
- H-C：按实际完整产品定知识/数据/媒体和真实业务权限、处理目的地、正式效果及成本策略。WeKnora 扩展证据只覆盖特定版本；不能宣布 v0.9.1 原合同自动适用。不强制旧 H2 预算/版本全闭包。未获真实许可不上传内部资料。
- H 环境：Daytona/其它批准独立环境先核实际 ARM64、Docker/Compose、网络及权限；Instabox amd64 仅对应 x64 证据；用户 Mac 非必要不运行实验。原始 H1/H2 受控日志未取得，只沿仓库的历史限定证明引用，不发明复跑。

## 5. 停止/反转规则

真正不可接受的制品、安全隔离、必要业务共享/正确性、长期大范围 core fork 或重复通用宿主，且成熟原生/上游修复/有限适配无法解决，才定向重开主体裁决。个别解析器/知识库/模型/存储/可选执行服务不合格先局部替换。正式业务错误、真实越权、实际硬限绕过仍为硬底线；不得用关闭必要业务、模拟真实效果或延期应在 G 完成的必要公共机制冒充满足。
