# 正式 W0 设计 · 一条可交收据的任务

**目标**是让一个获授权用户经真实宿主 API 提交一项任务，得到本人可读、可追溯且内容合格的结果。W0a 走确定性程序，W0b 把其中“如何取得证据”换成动态工具调用。两段共用身份、能力契约、业务服务、产品账、判定器、收件端和读回接口。实施与真实集成验收均须在设计独立复审、用户批准之后进行。

依据是 [PR #14 固定裁决](https://github.com/zhuquanwei111/mingjing---agent/blob/5761f44644a71b0ca3e54c76aa657fa3c681e22f/docs/designs/whole-product-decision.md)、[23 组 76 项验收表](https://github.com/zhuquanwei111/mingjing---agent/blob/5761f44644a71b0ca3e54c76aa657fa3c681e22f/docs/requirements/whole-product-acceptance-results.md)及[早期 W0-01～07 的定义](route-b-walking-skeleton-mvp.md)。[逐场景验收](w0-host-acceptance.md)是本设计的一部分。[首期产品范围](../requirements/first-mvp-product-scope.md)是并行的产品草案。

## 一个任务、一个收件人

合成场景为“核对一份已结束事项的资料包，把核对卡交到本人测试收件箱”。输入是任务类型、被授权对象、固定资料版本和客户端幂等键。身份、组织、资源权限从可信宿主会话及业务权限源取得；客户端提交的身份字段没有授予权限的作用。W0a 的程序从已发布的指定版本查询两项事实，例如开始、结束及其证据引用。W0b 看见的也是这两项完成条件，同一业务端可经工具取得目录和单项证据。待核时返回原因与可继续入口，不能编造缺失项。

核对卡同时绑定事项、版本、两项事实、可兑换的获准证据和目标收件人。验证器依据业务记录复核两项内容及来源；必需证据缺失、已撤回、版本错绑或验证服务不可用，只保存部分结果/失败原因。通过后才允许正式登记核对卡，然后向本人交付。业务登记收据、收件收据、用户阅读是三件事。“完成”要求相同任务和版本的质量通过、正式登记有权威收据、唯一交付已被收件方持久接受；用户可再凭当前权限读回。用例只有一种结果形态；正式业务内容留给 MVP 验收。

## 真实宿主、接线与资源

| 边界 | 本设计所需的具体接线 | 验收时的权威记录 |
| --- | --- | --- |
| 登录及任务入口 | 从目标 App 后端的正常受保护请求路径发起。已有后端候选能识别登录会话、读取任务及按当前主体查询站内收件。设计采用薄适配转给 Python 宿主，保持原会话所绑定的组织、用户、资源范围、动作。桌面脚本可驱动同一公开 API。 | 实际宿主访问/拒绝记录与新进程状态读回；自行组装 JWT、假身份头、仅调用实验 API 不能作为目标宿主通过证据。 |
| 业务读取与写入 | 资源所有方提供已发布版本读取、按测试身份判定对象和动作，以及按操作号登记核对卡/查终局。仅有租户过滤不足以证明同租户内的对象授权。 | 有权和失权各一例的服务端决定、效果及收据；目标服务的授权/幂等接入待贯通。 |
| 收件与打开 | 选目标后端的本人测试收件作为唯一目的地。接收方在事务内按交付号去重，验证主体、当前权限、对象、版本，写收件记录和可查询收据。通知列表/已读能力可复用；可按交付号写入和查收据的契约需要接线或补充。只交受控引用，再打开时重新鉴权。 | 收件端逐请求记录、已接受的唯一收件行、按交付号查询及本人/无权者读回。Python 的“发送成功”字段或页面提示不算收件证明。 |
| Python 产品宿主、PG、Temporal、Pydantic AI | 复用 #14 的职责和公开接口。产品账记录意图、授权依据、状态、操作及预算；引擎只传必要引用。#6 的质量函数需先验证输入/输出与真实收据一致再接入。业务和收件方可共进程，保留各自最终判定及查单接口。 | 产品记录、真实 Temporal 历史/Worker、隔离模型收端、业务方及收件方可独立交叉核验。 |

**接线确认点。** 以上来自现有候选后端的静态核对；当前在用宿主版本、其测试身份源与可用测试实例尚待确认。实施申请需标明宿主所有方、固定提交/构建、测试入口、可授予/撤销的资源及收件回查位置。在授权范围内只连接与生产隔离的**真实宿主副本**，使用种子的合成账号、资料、接收者；同一后端正常鉴权和业务执行代码须实际运行。旧代码只提供部分接口，服务凭据不能代替用户当前权限。目标宿主若另有其人，改接线映射并复核受影响场景；可先保留设计判断，不能把替身服务结果登记为宿主已验。无须为 W0 上线新 UI。运行证据内存放内部版本索引，公开仓库只保留合成标识和脱敏收据。

## W0a 从受理到交付

1. 入口验证会话。首次请求在产品库同一事务创建 Task、一次 Run、唯一启动意图及资源预留（有额度要求时）。同一组织/发起人/幂等键且同请求摘要返回原任务；同键异载荷拒绝，另一主体不能凭同键获取记录。缺必要输入先澄清，不派发。
2. 派发器用产品 Run 派生固定 Workflow ID；启动响应丢失先按原 ID 查当前/已关闭运行并核对绑定。竞争领取、网络重试与终止后同键重提均不得启动第二条逻辑运行。各 attempt 单独留痕。后续有意重开须显式新 Run；实施时锁定冲突与重用策略。
3. 确定性能力按**当前**资源权限读取指定版本并形成待验结果。质量判定在正式写入/交付之前；记录输入证据摘要、规则版本、分项结论以及验证失效原因。写入业务服务在提交事务内终核对象权限、质量引用与不可变内容，按稳定操作号记录效果及收据。
4. 收件方使用另外的稳定交付号，原子记录被接受的对象版本与收件人。业务已成、交付明确失败时分别保留，显示部分完成与后续处置。交付请求已到、回执丢失时只查原号；接收方确认已收再补记，不新建交付。无法权威查询则保持待核。有依据证明从未受理、权限仍有效且接收方保证同号去重，才允许同号重试。宿主只在获可信收据时标记交付完成；已撤权者不能打开先前引用。
5. 真实宿主按当前身份返回进度、等待理由、分项/最终结果和收据引用。客户端离线可重新查询；未知、已取消、已生效、已交付单列。客户端刷新不派生新的业务操作。

## W0b 在原链路内动态取得证据

模型只能在当前已发布、相关且获准的能力中选择。保留两个小工具：`list_evidence` 返回受控目录/引用，`verify_item` 用该引用核查单项结果，可进入异步待核。直接 API、工作流和 Agent 引用同一能力标识/版本和实际服务门禁。对固定证据已完整、缺某项、需先查目录等输入改变路径；用新生成的引用验证后续选择确实使用了上一工具的返回。模型输出只提出行动。登记核对卡及收件仍走 W0a 的质量、权限和收据链。

- **每轮模型。** 先以产品操作+模型轮次唯一认领，在事务内固定预算及可恢复状态，再外发；实际传输前终核。确认模型到达但未得响应或声明已写而是否到达未知，新进程保留该轮预留与待核。无供方权威记录时列人工核查，不假定可安全重发，亦不捏造回复。原始模型协议的受控接收器只用于精确计数，真实模型业务效果单列。
- **每个工具。** 以原操作号和调用 ID 保存受控消息、来源及会话引用；工具已经生效但结果入账前崩溃，先查原号，未知则保持可被通知唤醒的工作流。两个通知竞争同一结果时只核销一次；有权且资料仍有效才按原调用和会话继续。错 ID、签发方不符或旧版本不可读，保留原件待核/隔离。
- **授权与交接。** 读取、模型发送、工具发送、业务正式写入、结果交付分别核最新主体/对象/动作。模型及工具服务通过可控发出边界交接第一份受限数据，业务服务和收件方独立终核；撤权与首次交接须有可验证顺序。无法确认新鲜性/排序时关闭对应受限出口。先交接才撤权则保留在途事实，阻断其后新增动作。取消停止新派发，向支持取消的操作发请求；先前效果和迟到费用继续查实。
- **恢复与发布。** 轮次、检查点格式、能力、规则、来源及模型配置与 Run 绑定。停接旧版新任务后处理在途，兼容则按原语义读回，不兼容保留旧 Worker 或隔离；回退后按业务和收件收据核对。只读交易记录、受限模型上下文与可查询状态各自保留；限制网络/凭据、降级及无进展的证据列在验收表。

## 实施及停点

复审判断设计及判据能否执行；用户批准后才可开始 W0a。运行前锁定目标宿主/测试端、源码、各依赖和镜像摘要、数据库/角色/命名空间、工具版本、规则和受控模型配置，验证隔离网络及持久存储。实验基准可参照 [#12 固定版本和原件](https://github.com/zhuquanwei111/mingjing---agent/tree/300868efab379fa53ef0c49065b5cb6de36594ac/lab/product-review/round-gate/evidence/45195650384)。保持旧 P1/P2 与 #6 的任务、资源和在途记录隔离；只选择性引入已验证接口、测试或质量逻辑。

W0a 所有必需场景实际通过才进入 W0b；W0b 完成后在同一最终组合重验两段并独立审查实现与原始记录。必需出口缺权威、泄露、未知被错误释放、重复正式效果或错误交付，立即关闭相应路径并重审责任组件。W0 结果逐条带入首期产品的实施方案；业务负责人确认范围，再发起**独立的 MVP 实施方案评审**并另行决定正式开发。
