**状态：架构过渡基线（2026-11-26）。** 本文记录 F03 v1.1、F04、H/H1 与总控裁决的可公开摘要：Mastra 主体技术路线已确认；公共宿主从零建设；WeKnora 仍为条件主选，B04 完整准入未通过，待 H2 解决。此文档 PR 合入后成为新开发决策的导航及约束，不等于完整架构最终放行、锁定全部发行物或授权实施。新旧路线均不得凭本文件启动正式开发。历史 PR #14、旧代码及证据保留。

## 1. 建设目标与基本决定

面向完整产品，以实际效果、安全、可靠性、长期维护与复用价值决定技术。重点开发明镜独有业务，不重新建设已成熟的通用运行、知识、身份、权限计算、评测或管理基础设施。普通程序、固定 Workflow、动态 Agent 和独立外部能力共享授权与能力合同，不强制所有任务调用模型。M 是首个正式业务开发阶段，不是全部产品；G 的全部必要公共能力须先实际建成并验收。软件许可及必要平台订阅原则上零费用，模型、计算、存储、外服和运维成本另算并按授权管理。

## 2. 唯一条件性架构主线

| 职责 | 采用方向与边界 |

| 知识库 | WeKnora（H1 v0.9.1）与 A07 原生解析/检索/Wiki；MinerU 许可条件、必要原件定位与模态能力待验；B04 未完整准入，RAGFlow 只是有限备选，不能并装或擅自改选 |

上述不是购买、部署或精确制品锁定清单。知识域原生数据库搜索扩展、队列及存储兼容性不得由表中名称推断。实际主机容量、费用及生产目标仍待确认，不把潜在用户数视作并发。

## 3. 状态、权限与费用的权威

用户 Task 的意图、受理键、Run 绑定和业务结果由产品 PG/实际资源权威负责。每个 P1/P2 Run 的过程、检查点和代次沿用 Mastra 原生 Store；P3 若启用则仅由 Temporal 历史负责。不得另建通用状态机、第二个调度/重放系统。Session/Memory、当前合法上下文、正式业务事实分开。外部效果、实际费用及独立交付以资源方、供应商和收件方可查收据为准，原生 Run 成功或 Trace 不代表完成。

真实读取、模型出站、工具出站、正式提交、受限交付五处逐次核验当前身份、资源、版本、用途及授权。撤权与实际不可撤回交接有可查顺序；旧 Worker 不能通过缓存或凭据绕行。先停止新增，保留合法已生效事实；迟到回执仅获准核对。取消不是已发生效果的撤销。逻辑 Operation 与每次物理 Attempt 区分；原子认领并预留可证明的费用上界，可能已发送时保留 UNKNOWN/待核及预留，真实回执唯一核销，不能盲目重发。模型/工具/解析的内部重试同样受控。

## 5. 新能力如何接入（设计契约，尚非可调用 API）

开发者提供稳定 Capability ID/version、用途、输入输出 Schema、处理函数/Workflow/Agent 或外部适配器、发布及许可条件、真实读写/副作用、成本上界、超时、幂等、查单、取消/回执、质量规则和契约测试。普通程序可直接受理，固定流程和动态 Agent 复用同一个已授权的能力实现；登记、正式发布、授权发现和实际调用是独立动作。新任务固定 Task、原生 Run/owner、版本及操作身份；未获权、未发布、不兼容、未知或预算不足不得放行。能力不自行重建调度、权限、账本或交付系统。

旧[接入指南](whole-product-decision.md#capability-onboarding)及 [P2 实际接口](../../core/README.md)是可核的历史契约/测试资产，不是新 TypeScript 宿主已经具有的端点。实际新宿主实现后补接入手册、Schema、鉴权、真实接口和测试。AC-17 在 G 基座稳定后冻结构建，由独立接入者盲接未预置中立能力，记录实际核心改动并验证真实授权、计量、效果、评测及交付。

## 7. 迁移与不做事项

旧 P1/P2 代码、CI、历史需求与验收保留；不更改或删除它们，不把 Python/Temporal/Pydantic AI 作为新主体默认部署。旧候选中的契约、质量库及故障测试只在核兼容并复验后复用。旧任务分支不自动继承本次变更；并行的阶段计划、归档、知识、身份、目录 PR 合并前须对齐现行入口及裁决，不得重新激活旧路线。不得把旧 CI 通过认作新组合通过。
