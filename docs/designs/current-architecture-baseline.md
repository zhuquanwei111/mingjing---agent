## 1. 建设目标与基本决定

面向完整产品，以实际效果、安全、可靠性、长期维护与复用价值决定技术。重点开发明镜独有业务，不重新建设已成熟的通用运行、知识、身份、权限计算、评测或管理基础设施。普通程序、固定 Workflow、动态 Agent 和独立外部能力共享授权与能力合同，不强制所有任务调用模型。M 是首个正式业务开发阶段，不是全部产品；G 的全部必要公共能力须先实际建成并验收。软件许可及必要平台订阅原则上零费用，模型、计算、存储、外服和运维成本另算并按授权管理。

## 2. 技术主线与启用条件

**执行类型记号：** 本文以 EXEC-0、EXEC-1、EXEC-2、EXEC-3 表示 F03 v1.1 原称 P0、P1、P2、P3 的四类执行方式，一一对应且不改变技术选择、职责、条件或测试范围。它们不是开发阶段；旧工程规则的 P0–P3 仍专指开发阶段（见[阶段衔接](#stage-gate-crosswalk)），旧 P1/P2 代码及 CI 名称不改。

| 职责 | 采用方向与边界 |
| --- | --- |
| 应用运行 | Mastra OSS、Mastra Server、TypeScript、Node.js（F03 Node 24 LTS 参考）；复用原生 Agent、Tool、Workflow、Memory、会话与运行 API，不自研另一通用运行器 |
| 普通与动态执行 | EXEC-0 直接程序；EXEC-1 原生短 Agent/普通 Workflow；EXEC-2 原生持久 Agent（H1 限定机制验证）；一个 Run 一个执行所有者 |
| 严格固定耐久流程 | EXEC-3 仅在必要时用官方 Mastra-Temporal 转换支持的固定子集或 Temporal OSS 原生 TypeScript SDK，二选一；原生满足可取消 EXEC-3，不接管 EXEC-2 或双调度 |
| 持久事实与事件 | PostgreSQL 17 系列：原生运行存储和独立产品事实/操作/预算事务；按需 Valkey Streams 用于原生事件/续流，非业务事实权威 |
| 公共宿主和身份 | 明镜应用后端尚未建设；Keycloak OSS/OIDC 为身份接入，Mastra Server 复用应用运行服务；受控入口、独立交付和必要产品事实纳入公共基座 |
| 资源授权与出站 | SpiceDB OSS 关系授权，真实资源端终核，唯一可信出站责任边界及可验证旧执行者栅栏；PG 本地事务不等于跨网络原子性 |
| 公共数据 | Apache Hop GUI/Run/Data Validator、PG 暂存及正式发布；原生处理状态与质量、正式发布/撤回分别记录 |
| 原件与产物 | SeaweedFS OSS S3、AWS SDK v3、固定版本及字节校验、受控读回；不把长效签名链接当权限 |
| 知识库 | WeKnora v0.9.1 原生解析、检索与 Wiki；同权限知识域、固定来源、独占编译批次及父预算。撤回先关闭旧版，按影响域从合法原件干净重建，验证后受控发布。复杂版面、模态、实际费用及多活动批并发待 G。 |
| 模型 | Mastra AI SDK 原生 provider/公开传输扩展；F03 模型及嵌入/重排仅为待授权和评测的参考配置，供应商及真实价格未定；所有实际外发受控，不默认另建模型平台 |
| 管理与质量 | 可信工程域免费 Studio、Hop/WeKnora 原生工作台、Keycloak 管理、必要 React-admin OSS 页面；Mastra Scorers/Evals/Observability 与 Vitest；确定性质量门、实际审计、费用独立，免费功能须按实际生产制品核验 |
| 部署与恢复 | Linux OCI/Compose/Caddy、Prometheus/Alertmanager、pgBackRest/restic；真实制品、许可、兼容、资源目标及恢复条件待实施前确认；PostHog Cloud 保留历史条件方向，接通/授权未核 |

上述不是购买、部署或精确制品锁定清单。知识域原生数据库搜索扩展、队列及存储兼容性不得由表中名称推断。实际主机容量、费用及生产目标仍待确认，不把潜在用户数视作并发。

## 3. 状态、权限与费用的权威

用户 Task 的意图、受理键、Run 绑定和业务结果由产品 PG/实际资源权威负责。每个 EXEC-1/EXEC-2 Run 的过程、检查点和代次沿用 Mastra 原生 Store；EXEC-3 若启用则仅由 Temporal 历史负责。不得另建通用状态机、第二个调度/重放系统。Session/Memory、当前合法上下文、正式业务事实分开。外部效果、实际费用及独立交付以资源方、供应商和收件方可查收据为准，原生 Run 成功或 Trace 不代表完成。

真实读取、模型出站、工具出站、正式提交、受限交付五处逐次核验当前身份、资源、版本、用途及授权。撤权与实际不可撤回交接有可查顺序；旧 Worker 不能通过缓存或凭据绕行。先停止新增，保留合法已生效事实；迟到回执仅获准核对。取消不是已发生效果的撤销。逻辑 Operation 与每次物理 Attempt 区分；原子认领并预留可证明的费用上界，可能已发送时保留 UNKNOWN/待核及预留，真实回执唯一核销，不能盲目重发。模型/工具/解析的内部重试同样受控。

## 5. 新能力如何接入（设计契约，尚非可调用 API）

开发者提供稳定 Capability ID/version、用途、输入输出 Schema、处理函数/Workflow/Agent 或外部适配器、发布及许可条件、真实读写/副作用、成本上界、超时、幂等、查单、取消/回执、质量规则和契约测试。普通程序可直接受理，固定流程和动态 Agent 复用同一个已授权的能力实现；登记、正式发布、授权发现和实际调用是独立动作。新任务固定 Task、原生 Run/owner、版本及操作身份；未获权、未发布、不兼容、未知或预算不足不得放行。能力不自行重建调度、权限、账本或交付系统。

旧[接入指南](../archive/route-b/designs/whole-product-decision.md#capability-onboarding)及 [P2 实际接口](../archive/legacy-runtime/core/README.md)是可核的历史契约/测试资产，不是新 TypeScript 宿主已经具有的端点。实际新宿主实现后补接入手册、Schema、鉴权、真实接口和测试。AC-17 在 G 基座稳定后冻结构建，由独立接入者盲接未预置中立能力，记录实际核心改动并验证真实授权、计量、效果、评测及交付。

## 6. 阶段及硬门槛

| W0b | 同一宿主链路加入原生动态选择、模型/工具配对、进程恢复、撤权、旧代次、共享预算、取消及迟到结果；不是复跑 H1 即完成 |

### 新旧开发阶段门禁衔接（非执行类型）

根 AGENTS 引用的[原工程规则](../archive/engineering-v1/AGENTS.md)继续完整适用，其 P0–P3 是旧开发阶段，非 §2 的 EXEC-0–EXEC-3 执行类型。新路线使用上表 H/W0a/W0b/G/M/T/P 作为实际关口；以下对应关系用于保留门禁，不追溯认定旧验收可替代新路线验收，不改变原规则及需求原件。

| 旧开发阶段 | 新路线承接与继续条件 |
| --- | --- |
| P0（只读核验） | H 的只读前置核验负责仓库、依赖、许可、版本、最小代码入口及记录；H1/H2 的专项运行验证只有另行授权后才在隔离范围执行，不属于正式建设授权。未获正式实施批准，不得启动 W0。 |
| P1（隔离 Walking Skeleton） | 获准后的 W0a/W0b 承接新路线真实最短链路和最小必要宿主。按原 P1 门禁实际验证异构能力、故障、撤权、预算及版本升级；W0a/W0b 验收及原 P1 适用判据均通过并获确认，才允许转入 G 的正式公共层建设。若 W0 初步覆盖不够，先在已获准的隔离范围补齐所需 P1 判据，不能延期绕过门禁。 |
| P2（通过 P1 后建设最小公共层） | G 承接并扩大为完整必要公共基座。不得仅凭历史 P1/P2、H1 或 W0 单项成功批准 G；全部适用 G 验收（含稳定基座后的 AC-17）须实际通过、再获明确 M 开发授权。 |
| P3（按真实需求扩展治理与业务） | 必需公共治理仍在 G 完成，不推到 M；G 通过后才按批准范围开展 M 与后续扩展。真实试用和生产 T/P 分别另验、另准入，条件功能依原适用要求在启用前验证。 |

旧规则的业务、安全、编码、隔离、失败留证和停止条件同时适用；任一适用阶段失败或缺授权，不得跨关口继续，先提交原因、证据及解决办法。文档合并、H1 限定机制结果或旧 CI 通过均不解除正式实施暂停。

## 7. 迁移与不做事项

旧 P1/P2 代码、CI、历史需求与验收保留；不更改或删除它们，不把 Python/Temporal/Pydantic AI 作为新主体默认部署。旧候选中的契约、质量库及故障测试只在核兼容并复验后复用。旧任务分支不自动继承本次变更；并行的阶段计划、归档、知识、身份、目录 PR 合并前须对齐现行入口及裁决，不得重新激活旧路线。不得把旧 CI 通过认作新组合通过。

实施按[详细契约](architecture-final/contracts.md)与[工程门禁](architecture-final/gates-and-risks.md)接续。产品计划中的首期业务沿用“跟播—复盘—次日妆造预约”；首期之后的功能按批准阶段验收。
