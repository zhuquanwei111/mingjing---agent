## 1. 建设目标与适用口径

面向完整机构产品，不把首期业务或约300潜在用户误作并发/全部需求。原生设计优先，允许合理变通，优先实际效果、安全、业务正确、维护成本及长期发展。直接普通程序、适用固定流程、动态 Agent、异步任务合理共享实际业务能力，不强迫同一引擎或全部经模型。G 完整必要公共基座实际通过并获准后才进入 M 正式业务。原 v0.4.1 仍保留原件，已批准 R3 修订覆盖冲突旧判据。软件许可及必要平台订阅原则上零费用，模型、算力、存储及运维另核，不未经授权购买、部署或上传资料。

## 2. 技术责任与决策边界

| 职责 | 当前采用方向 |
|---|---|
| 主体应用宿主 | DeerFlow OSS（ByteDance MIT 根项目依据原独立核查；实际制品依赖需核）。研究固定 v2.2.0 `58fc5bd5b8e6ea46538e9481ba06ca2a46e14e2a`，实际安全发行/提交、镜像 digest、依赖在 H 确认。继承 Gateway、用户/会话/线程、运行事件、Agent/子任务、管理及扩展，不另造完整应用宿主或改写 Agent Loop。 |
| App/身份与权限 | 明镜应用后端尚未建设。App 入口的服务端身份映射由必要公共接线承担，实际身份源待 H 确认；优先原生 session/OIDC、owner、工具授权 Provider/Guardrail 显式启用及 fail-closed。业务资源由可信现有/必要业务服务核权；非 SaaS 多租户。不把 host admin/user、内部共享 token 或模型参数当业务主体。 |
| 普通/固定/动态/后台 | 普通程序与确定性规则直接业务接口；Agent 走原生工具/插件/MCP。原生 scheduler/MCP Tasks/适用工作流及既有任务服务按需。确需持久无人值守才采用合适成熟机制，不默认 Temporal 或统一调度。 |
| 持久化及交付 | 原生支持的运行/检查点、事件、线程/记忆、必要文件管理；实际部署选择上游支持的 SQL/流/沙盒资源。业务事实、正式操作、真实收件和费用分别以相应权威为准；必要 ID 关联，无全局总账强制。 |
| 知识与公共数据 | 先考察原生知识 Provider/检索/管理接线和成熟知识库原生机制；WeKnora v0.8.3 接线有上游局部实测，旧 v0.9.1 非新主线自动锁定。管理空间不是聊天 ACL。业务事实走真实 API；普通资料可直接处理使用，正式资料按需发布；必要复杂文档/音视频/视觉定位按实际完整需求。 |
| 模型/上下文/质量 | 原生模型配置、上下文、工具协议及观测/扩展；真实外发目标和模型兼容性验；条件记忆按需。重要正式结果必要确定性校验，原生和成熟评测优先，不另造通用评测平台。 |
| 费用/运维 | 原生限流、步数、时长、并发、Token/供应商配额及告警；确有硬限才严控。按实际负载、许可、目标环境与风险选择部署、备份及回退，不预设双域灾备。 |
| 旧组件 | Mastra/Server/SDK/Store/Studio 不再是主体默认；其真实业务契约/测试/历史证据保留。Keycloak、SpiceDB、Temporal、Hop、SeaweedFS、WeKnora、模型和观测等按实际缺口及成熟工程复用决定，不因旧选型或新主体自动采用。LibreChat 为优先备选，Omnara 为对照。 |

## 3. 状态、安全和费用的权威

原生运行状态说明执行过程；业务服务、实际供方、受权交付端负责正式业务效果、真实费用和交付。允许各执行方式按各自原生状态运行，只要用户任务结果和必要关联可信。模型不授予身份或权限，资源端保护真实读写及新访问；常规权限变化按批准的合理规则处理，允许已有合法分析有界继续或暂停、提醒、终止；新无权请求/正式操作/非法外发拒绝。普通资料撤回后停止新检索与使用，历史合法输出默认保留；特殊许可按实际要求。未知正式效果查证或可靠同意图重试，普通工作可合理重做；取消不回滚已发生事实。普通费用有界，真实硬限可靠控制。不得将模型/运行成功等同真实业务完成。

## 4. 新能力如何接入（设计要求，非已存在的接口）

开发者提供清晰输入输出、用途、版本、实际权限、重要副作用/错误及必要质量契约；普通函数/API 或原生插件/MCP 各按适用方式接入。能力可用不代表获准，资源方核权及正式业务逻辑复用。确定操作不强制 LLM；长任务按实际业务时效采用合适的原生或成熟执行机制。无需另建统一注册/调度/操作账本。G 基座稳定后，由未参与原接入的人盲接一项事前未适配的实际中立能力，记录核心改动及实测结果。AC-17 纳入 G 签收，须在首个 M 前完成。

## 5. 历史与当前证据

R3 原始送审、独立最终裁决与用户决定提供主体选型和现行需求依据；上游源码/局部运行报告、企业案例及旧 H1/H2 仅按各自证明范围使用。独立裁决认定身份与隔离（A）、异构能力共享（B）、知识与正式结果及费用（C）均在限定条件下可行，原 A 阻断解除；没有新增明镜运行实验。研究参考版一个后端 CI 分片失败，完整原因未知；H 核实际安全制品及受影响路径。不得将 v2.2.0 或未发行 main 当生产批准版。

## 6. 阶段及硬门槛

- 本次基线迁移：一致更新设计与规则，独立审查及适用 CI，用户人工合并；不自动开工。
- H：实际安全制品、许可、部署、App/权限接线、必要适配与成本风险、测试环境和 W0 批准。只核决定实际投入/制品的必要事项，不重开全行业选型。
- W0a/W0b：另获准的真实最短受控链路，普通/动态/适用异步共享业务，真实资源/身份/权限、质量、效果、合理异常；通过并另获项目方批准后进入 G。
- G：完整产品必要公共工程、实际可用用户/管理接口、适用 76 项及 AC17，按需启用条件能力，不能延迟必要机制到 M。
- M：G 实际通过且另批，首期支持“跟播—复盘—次日妆造预约”和“只复盘”两种路径；真实业务各自验证。
- T/P：实际容量、安全、许可、成本、回退、恢复与正式流量审批。

<a id="stage-gate-crosswalk"></a>
### 新旧阶段衔接

P0→H；P1→W0a/W0b；P2→G；P3→M 及以后。旧规则保留有效目标、适用门禁、安全和真实证据；R3 对严格机制/判据的修订在冲突处优先，详见[现行需求](../requirements/current-engineering-requirements.md)。旧 EXEC 分类是历史实现记号而非现行必须结构。不得用旧验收或本次文档 CI 代替新阶段。

## 7. 停止与迁移

发现严重不可处理制品缺陷、基本隔离/必要业务能力无法合理实现、需广泛重写核心/重复公共平台且长期收益丧失时，停止受影响工作并定向复核主体；先核上游修复和局部替代，不因普通组件缺口重启全面评审。旧 P1/P2、F03/F04/H1/H2、旧技术矩阵与原件作为历史；保留现有回归/CI，禁止误删。合并及开工按工程规范由用户批准，旧分支不自动继承新基线。
