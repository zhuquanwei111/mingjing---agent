# 05 安全、授权、预算与可靠性

## 身份和授权
- 入口认证只建立可信主体，不自动获得所有业务对象权限。
- 执行前检查主体、租户、能力版本、具体资源、动作、委派范围和授权有效性。
- Agent 不因创建者或模型声明自动获得创建者的全部权限。
- SpiceDB 可复用关系求值，但 Schema、租户边界和委派链需安全测试。
- 缺失授权关系、关键服务不可达或策略异常时不得默认允许敏感操作。
- 发布/灰度开关不是授权；无发布规则不得自动默认上线。

## 幂等和副作用
- 区分客户端请求键、task_id、workflow_id、run_id、operation_id、attempt_id、供应商请求 ID。
- 稳定逻辑 operation_id 跨引擎重试保持不变；真实外部尝试必须独立计量。
- 同库写操作应在同一事务内记录业务结果与收据；跨外部系统无法保证同事务时须有查询、对账、补偿或结果未知流程。
- Temporal Activity 至少一次执行，重试不能保证业务恰好一次。
- 对无法查询结果、也不支持幂等的外部服务，未知状态不盲重试。
- 补偿是业务定义，不是引擎自动回滚现实世界。

## 预算
- 在实际付费 I/O 前由可信服务检查并预留预算；数据库不可用时硬预算请求拒绝。
- 并发预留需要事务与稳定锁顺序。
- 取消、超时、模型回退及供应商回执丢失可能继续产生费用；未知费用不自动记零。
- 观测事件和财务/业务账本分离；重复上报不等于重复真实花费。
- 无可信成本上界时不得承诺严格零超支。

## 审批
- 审批请求有稳定 ID、资源、动作、参数摘要、申请人、审批人和期限。
- Temporal Signal/Update 可传递审批决定；审批身份在明镜可信 API 核验。
- 审批通过到正式执行之间可能撤权；实际 I/O 前重新核权。
- 取消仅表示停止后续动作的意图，不意味着已经提交的动作不存在。

## 执行隔离
- 默认硬化 Worker：非 root、最小权限、凭据隔离、资源上限、最小网络访问。
- Worker 进程隔离不等于不可信代码沙箱。
- 需要执行任意代码时先评估 gVisor 等沙箱，不直接将任意代码跑在拥有生产凭据的 Worker 内。
- 不可信执行器必须独立限权、计量和取消。

## 观测与审计
- OTel 追踪可以采样；权限决定、写入收据、审批和资源账不能采样丢失。
- 默认不把敏感 prompt、文件、凭据或完整业务响应发送到第三方观测系统。
- 关联 task/run/operation/attempt ID，但不能用 trace_id 作业务幂等键。
