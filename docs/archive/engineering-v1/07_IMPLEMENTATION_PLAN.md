# 07 分阶段实施计划与门禁

## P0 — 只读核验与新仓库准备
目标：建立干净的新仓库、记录工程事实。
任务：
1. 确认仓库无既有业务代码；初始化 README、AGENTS、docs、tests、src。
2. 核对 Temporal Server、Python SDK、LangGraph、temporalio-langgraph 的固定版本、依赖、许可、官方样例及兼容范围。
3. 核对 PostgreSQL、对象存储、开发环境和容器运行权限。
4. 编写 DEPENDENCY_LOCK.md、RISK_REGISTER.md、验证矩阵与启动说明。
交付：可审查的 P0 报告；不自动宣布插件兼容。

## P1 — 隔离的 Walking Skeleton
目标：只实现足以验证选型的最小闭环。
任务：
1. API -> 普通程序能力；无需模型。
2. API -> Temporal 异步工作流；外部等待、进度、恢复和取消。
3. Temporal -> LangGraph Agent Loop；受控工具调用。
4. 三种入口调用同一受控业务能力，统一 task/run/operation 标识。
5. PostgreSQL 模拟业务写入与收据，故障注入：提交成功但回执丢失。
6. 审批、撤权、预算并发与 Agent 深度/步数边界。
7. 旧 Worker 与新版本兼容或保留策略测试。
交付：测试代码、日志/数据证据、实际修改文件清单、P1 结果报告。
门禁：若有核心侵入、无法可靠恢复、权限绕过或重复副作用，停止并说明替代路线。

## P2 — 最小明镜公共层（P1 通过后）
目标：形成可持续扩展的真实应用骨架。
任务：
1. 能力契约、版本化注册/发布/授权、执行适配。
2. 产品 Task/Run API 与执行状态映射。
3. 可信身份和资源授权入口；必要时评估 SpiceDB。
4. 业务幂等收据、结果未知处理、审批、预算预留与结算。
5. 产物元数据与授权访问、审计、OTel 关联。
6. 三类能力 SDK 模板与契约测试。
交付：API、迁移、测试、操作手册和版本管理方案。

## P3 — 按需补齐
只在需求和验证触发时接入：独立模型网关、关系授权服务、AI 观测平台、跨资源计费、知识解析检索、代码沙箱、可视化控制台。
每引入组件提交复用收益、部署依赖、许可、升级责任和退出方案。

## 每阶段结束模板
- 已完成和未完成
- 使用的仓库、Tag、镜像摘要和许可证
- 运行步骤与复现命令
- 自动化测试结果及故障注入证据
- 关键代码新增/修改列表
- 失败、风险与替代路径
- 下一阶段所需授权
