# 明镜智能体现行工程需求

**生效版本为 2026-11-27 合并至 main 的 DeerFlow 基线。** [PR #29](https://github.com/zhuquanwei111/mingjing---agent/pull/29) 已将 R3 裁决和 D01–D13 写入仓库。开发前先用本页确定需求的适用范围，再按[76 项映射](final-architecture-mapping.csv)中的原编号查看现行要求、可观察结果和验收关口。根规则和[阶段门禁](../designs/architecture-final/gates-and-risks.md)共同约束施工。

- **主体与调用。** DeerFlow 是唯一主体应用工程底座。查主播开播时间时，普通业务接口按员工权限直查排期，模型调用为零；分析直播表现时，由 DeerFlow Agent 通过授权工具取用资料。工作流、异步任务和调度优先复用 DeerFlow 原生能力。两条路径共用相同的资源权限和业务事实。见 [ADR 0003](../adr/0003-deerflow-architecture-transition.md)。
- **需求与证据。** 完整产品面向一家机构约 300 名潜在用户。v0.4.1 原件保留未修订的业务目标、安全与质量要求；明确冲突处按下表 D01–D13 执行。知识专项的岗位、使用目的和素材许可按实际业务核对。知识库、模型和具体部署制品仍按其适用关口确认；原 Mastra、路线 B、旧供应商实验及历史验收只用于追溯。[历史资料导航](../archive/README.md) · [原件指纹与裁决依据](../tasks/architecture-baseline-transition.md#决定与证据定位)
- **开发与验收。** 本次已完成主体和仓库基线切换。H 确认安全制品与接线条件；W0 另批后才使用真实测试身份和中立资源验证。G 签收包括全部必要公共能力，以及由未参与原接入的人盲接事前未适配能力的 AC-17。G 通过、首个业务方案独立评审并另获批准后，才能进入 M。跨期条目分别记录隔离证据和真实业务证据。

## 知识库岗位需求如何沿用

项目方已在 #23 确认七个范围的岗位任务：机构制度与岗位协作、主播经纪与人才培养、内容创作与素材、直播与制作运营、商务、客户与项目交付，经营、财务与合规、行业研究与组织经验。该 PR 后来关闭，已确认的岗位需求仍从固定原件追溯。[确认记录](https://github.com/zhuquanwei111/mingjing---agent/blob/7575c06a0431c1289cfddb702eef3ae5e839a9fd/docs/requirements/knowledge-base-requirements.md) · [已确认原件及四家同行出处](https://github.com/zhuquanwei111/mingjing---agent/blob/43b6f2384bd8d9afc54ec0f0bda26fb9117a1d25/docs/requirements/knowledge-base-requirements.md)

例如，编导交素材给商务，商务按客户许可向客户交付，并按独立的教学许可把教学版入口交给带教。带教从本人收件处核对版本与用途，确认查收后才用于课程。原件修订时由教案负责人核对引用并更新课件。教学许可撤回后，学员重开旧链接不能再取到受限片段；商务按独立的客户许可判断是否需要通知收件人。普通撤回按 D03、D07 停止新的检索与使用，已合法产生的历史原则上保留。具体素材许可另有要求时，核对其适用版本、用途和交付范围。正式检索、发布和撤回分别按 FR-22、FR-23、AC-09 的现行判据验收。

## 已采纳的决定（全部纳入）

|决策|现行口径|不再强制|实际底线|
|---|---|---|---|
|D01 原生设计优先|成熟工程已有合理处理机制优先；证明实际业务问题或不可接受风险才补充，允许合理适配和组合|以旧架构的技术机制、实现形式或组件数限制候选|实际效果、安全、业务正确、合理长期成本；同等对待候选|
|D02 运行中权限变化|例如运营分析期间调岗，可允许当前已准分析完成、下次访问拒绝，或暂停/阻止/提醒。按实际风险与原生边界选择；不得无限延续旧授权|所有受限读/模型/工具/交付必须在同一撤权时刻全局原子阻断；强制任务 scope 整体失效|可信身份与资源授权，新的未授权访问不放行；新用途/接收方/正式操作适用授权，紧急事故按真实需求有效控制|
|D03 资料撤回与历史|普通资料过期/撤回后停止后续检索和使用；已合法产生的历史对话、回答、摘要、记忆、文件原则保留。特殊保密、合规、素材许可确有需要时另行处理|全量历史回答及派生产物来源追踪、逐段隐藏、默认整会话遮蔽或自动回溯修改|当前原件、旧下载链接的实际新访问、后续正式检索不得绕过有效许可；历史保留不是允许复用撤回资料作新事实，也不是许可他人读私人历史|
|D04 单机构权限（八项01）|约300名潜在用户的一家机构，原生用户/角色、资源授权与必要隔离优先|企业SaaS多租户体系、每部门完整独立运行空间|不同人及岗位的无权访问、伪造主体、非法外发不得发生；300不是并发目标|
|D05 异构执行（02）|普通业务接口可直接执行确定性操作；DeerFlow Agent 承担动态分析，需要工作流、异步任务或调度时优先用 DeerFlow 原生能力|另建统一注册中心、全局调度器、统一执行账本；所有业务都通过模型|不同入口复用同一业务能力，实际资源方核权并返回正式结果|
|D06 后台恢复（03）|可安全重做、补跑、从检查点继续、人工恢复或失败提醒，按时效/损失选择原生机制|所有任务精确/自动无损恢复、零重复模型请求或任意位置重启接管|重要任务依实际业务达到必要可靠性，正式效果不可盲重做，失败和部分完成如实呈现|
|D07 来源与派生更新（04）|知识手册更新后用原生重处理、索引更新或相应库范围重建；保留必要原件/版本/引用|每个条目、Wiki、图谱、摘要构建完整来源依赖图及实时级联更新|新的正式检索不能把过期、失效或无权内容继续当有效资料；保留必要证据，来源不捏造|
|D08 入库与发布（05）|普通教学/工作资料可以原生处理后直接查询；重要财务/制度/正式许可按实际需要审核和发布|所有上传都必须走独立的受理、解析、质检、人审、发布多阶段工作流|普通可查询不等于自动提升为权威制度/合同；确需质量/发布条件的资料必须符合条件，仍保留错误处理|
|D09 外部未知结果（06）|视频生成/解析等超时可等待、查询、有限重做、告警或人工；按费用和结果风险决定|所有第三方都具备强自动对账、结果核实及恢复机制；每物理请求恰一次|预约/支付等正式效果不得不可接受地重复；未知不能假报成功/失败，明确的高成本或资金硬限仍须可靠控制|
|D10 技术成熟度（07）|接受合理新技术风险；现有生产案例、可信报告和维护是证据，非统一历史年限|等待广泛独立企业案例、所有无关测试绿才考虑采用|已证实严重安全/正确性缺陷、不可维护版本或不可接受运维风险不能豁免；CI根因未知需如实标注|
|D11 选型前验证范围（08）|只先处理可能改变主体选择的问题；其余正常工程接入与适用阶段验收|要求选型前解决未来所有业务合同、供应商细节和全部76项实测|不把设计可行冒充已验收；真正决定主体的高风险缺口仍核证；安全制品和实际能力上线前须满足适用门禁|
|D12 分层费用与灾备|原生 Token/步数/时长/并发/速率及资源配额、账单监测，实际硬限/高成本才严格；普通失败有限重试。灾备按业务损失和RPO/RTO|通用金融级共享货币预留、每次模型调用物理精确一次、高等级双域同步为默认|普通成本有界，真实硬限不被绕过，已花费用不假归零；关键事实保护和备份回退按需验收|
|D13 条件记忆、评测、版本|长期记忆按需启用；原生/成熟评测和观测优先，运行质量门按适用业务；合理停用、升级、回退或重新运行|独立记忆/评测/观测平台、全部人工审核、所有状态强版本迁移|正式结果质量、可复核来源、必要审计/回归、安全配置与实际备份恢复仍需要|

说明：D04–D11 为用户最终一次性采纳的八项建议；D01–D03、D12–D13 为此前已采纳方向的统一整理。不同任务的具体策略并未由用户固定为一种。若原生行为合理即可使用；新业务若有特别强制限制，针对其具体边界再设计，不将它自动扩展为所有业务的先修平台。

**工程规则的适用澄清**：历史 v1 仍有效的实际敏感正式写操作重新核权、关键安全门禁默认拒绝、正式副作用不可盲重试、真实审计与事实、隔离与密钥安全、独立评审和 Git 规则保持。已批准的只读分析按有界有效授权规则继续不等于允许新越权；旧 `统一记录` ID 改为按实际所需关联，不把缺失不适用 ID 当失败。多个不同执行方式可以共存，但同一正式效果不能有多个冲突权威。必要恢复时效、实际资金硬限和特殊许可有明确要求才设严格条件。旧阶段 P0–P3 与新 H/W0/G/M/T/P 的对应门禁继续适用其真实目标，不恢复取消的过度判据。不得以本说明削弱真实安全、业务正确性或 G-before-M。
