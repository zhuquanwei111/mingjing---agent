# 首期 MVP 产品范围草案 · 运营的单场复盘

**当前没有真实宿主。** 以下描述拟解决的用户问题与可观察的业务验收，入口与交付是未来的产品行为。初稿可与运营核对；真实业务试用取决于宿主就绪和 W0 实测。

**推荐的第一批使用者**为明镜 App 内一个运营小组中、对该场次有明确职责和当前权限的运营人员，先接受一个小组试用。每人只处理自己获准的场次；同组或曾负责不能自动扩权。主播为业务对象，本期只交回发起运营本人。首批人选、责任映射和具体资料供给须由产品/运营负责人确认。约 300 名潜在用户不作为试用规模或并发指标。

## 用户要完成的工作

一场直播结束后，运营需要知道“这场实际发生了什么、哪里还缺依据、下一场应跟进什么”。首期只选**已有、获准、可固定版本的一场资料**。运营选场后发起复盘，查看带来源的结果，必要时打开证据，确认可用于下一场跟进或退回具体缺项，随后能从本人任务记录找回同一版本。多人可分别负责同一主播；交回本人不扩大其他运营或主播的数据权限。

| 产品内容 | 首期拟定范围 |
| --- | --- |
| 输入条件 | 已结束的单场标识、当前运营与该场次的授权关系、一份固定版本资料包。注明实际开始/结束、时区、资料来源和适用范围；如有关键事件或运营记录，需能定位原处。资料取自已获准入口。首期不要求接平台账号、生产实时采集或多台机器并发取数。 |
| 可交付结果 | 一份仅本人可访问的《单场复盘草稿》。包含场次与事实摘要、至少一个来自资料的可定位观察（无依据时明确缺项）、可供下场采用或核实的建议、资料版本及不足。事实、推断与建议分别标明。所引数字保留原单位；没有换算依据不展示现金金额。 |
| 用户能做什么 | 选一场、发起、离开后再打开、定位证据、接受或按明确原因退回。资料被更正时保留旧版本记录，按新版本重新生成并显示变化；撤权后旧引用也不能重新打开。 |
| 业务完成条件 | 该运营能认出正确场次，逐条定位必需事实，理解一项可执行的建议或待核动作，并能决定如何跟进。仅有一份报告、工具返回成功或用户点开均不足以证明任务完成。无资料/无权/缺关键事实时返回具体原因及补充入口；部分结果单记。 |

## 由业务怎样验收

由产品负责人和一名承担日常复盘的运营在获得相应数据授权后确定样本集、参考事实、必须回答的问题和可接受的建议标准，**在首轮试用前锁定版本**。准备完整场次、资料冲突/不全、资料更正和关系已撤销的案例。包含正负例的运行按实际授权记录，回执只说明送达，用户反馈另记。试用中的业务验收不同于每项任务增加人工审批流程。

| 场景 | 业务验收人能观察到的结果 |
| --- | --- |
| 正常复盘 | 在本人入口找到指定场次。开始/结束等必需事实与权威记录一致；至少一条观察和对应建议能追到所列来源。运营能说明“下一场做什么、为什么”，并在业务验收记录中接受，或留下有指向性的退回理由。 |
| 证据不足或矛盾 | 明确哪一项不可确认、冲突来自哪个版本及应补什么。不能编出数字、归因、换算或把未完成草稿标为合格。 |
| 错场、失权或包被撤回 | 阻止该结果交付或再次兑换，其他场次或同组无权用户也读不到正文。保留已发生的审计事实。 |
| 更正与重开 | 用户能辨认旧、新版本及事实变化；相同资料同次重试不产生重复收件。已生效交付的历史不改写。 |

**价值判断。** 在同类授权场次上记录现行人工复盘耗时、试用耗时、事实错误、需返工项、可定位证据及运营接受/退回原因，给出真实分母和按场次对照。试用人数、样本组成、耗时/质量目标和适用范围由产品与运营在试用前确认，依据现行工作记录设定。没有基准时先记基准，不承诺百分比。当前未访谈指定试用者、未运行真实业务，也未批准这一范围为正式开发任务。

## W0 到 MVP 的交接

W0 的一个资料包、质量门、本人收件回执及撤权恢复能服务这条产品路径。W0 用合成资料和测试账号；单场业务语义、真实资料准入、建议是否有用、人工返工与稳定负载另用业务样本验证。键鼠采集资源在现行流程可能独占；首期从已有合格资料进入。若实际无法取得可授权、可核验的场次包，首期输入条件未成立，由产品决定先补获准来源或更换首项任务，不暗中加范围。

**定稿条件**为 W0a/W0b 有真实宿主逐场景结论，记录已证能力、失败、可接受限制、处理方式和变更的公共边界。再由产品/运营确认首批用户、来源、交付和试用判据，由工程负责人写 MVP 实施方案与停止/回退条件，取得独立评审和另行实施决定。实时提词、开播通知、对主播推送、跨场分析和资料采集扩容保留在后续产品范围。
