# 首期 MVP 产品范围 · 跟播、复盘与次日妆造预约

首批用户为明镜 App 一个运营小组中，对指定主播、场次和操作有当前权限的运营。一名运营可以负责多名主播，同组关系本身不授予权限。主播为预约服务对象，化妆师按排班提供服务，发起运营是本例的收件人。具体试用人选、可使用的场次及排班接口尚待接入。约 300 名潜在用户不能用来设定并发。

## 主验收用例

> 今晚小林开播后，帮我重点跟一下上次说要调整的开场互动，下播后结合本场数据和跟播记录做复盘，把哪些调整落实了、明天还要跟什么写清楚，复盘完成后就给她约明天下午最早的空闲妆造时段，哪位化妆师都可以，约好了把复盘、时间和化妆师一起发给我，下午都约满了就把其他空档列出来让我选。

同一运营发起一次，可离开 App、回来查看同一任务、补充指令或选择空档。分别记两项业务结果：① 能指导下场工作的合格复盘，② 排班实际生效的符合条件的预约。整句另核对先后顺序、条件分支、对象和本人收到的内容。其他任务可以单独调用同一能力。复盘质量门按业务约定执行；首期试用中的人工评价不增加逐笔人工批准。

**受理时确定意思。** 保存发起人、组织、主播稳定标识、场次或其绑定条件、已确认的改进项引用、原始接单时间与时区、目标日期、业务日历定义的下午区间、选最早/任意化妆师、依赖、收件人、变更版本。App 显示解析后的日期与对象。例如受理为北京时间 11 月 24 日 22:00，预约目标显示 11 月 25 日下午。即使下播时间为 11 月 25 日 01:00，次日恢复仍用 25 日。时区、同名主播或场次存在实质歧义时先取得必要信息，只暂停受影响步骤。开播事件按稳定场次关联，重复通知只启动一次。

**开播时开始跟播。** 收到已绑定场次的开播事件后，唤醒原任务，把“开场互动的哪一项调整”交给获准观察入口或当前负责运营；记录跟播开始时点、执行/接手状态与观察出处。直播期间按获准方式记录能定位的片段或带时点的观察，下播事件再触发 Ego Lite 取数，按同一场次汇合两路。重复开播只启动一份跟进。若始终无人接手、采录未开始，或只有事后补录，则如实标注实际来源、发生/补录时点与缺口，不能据此宣称已按时跟播。

**跟播和取数。** 上次改进项以获准的已确认复盘版本为准。开场行为可用获准片段的时间区间、带时间点和来源的运营记录等佐证。开播、下播、汇总指标各有自己的来源，登记使用权限、场次、时间、单位及版本。下播采集沿用业务已确认解决键鼠占用的 Ego Lite 路径；本次未进行业务端联调。若只有整场汇总，开场互动写为“待核”，不得推断已落实或未落实。源资料更正需标出变化，撤回后旧引用亦受控。

**完成与收件。** 复盘交代上次要求、本场逐项事实和定位、已落实/有证据未落实/证据不足、下场具体跟进建议。事实、推断和建议分开，数字保留原单位，缺换算依据不展示现金金额。关键证据清单在业务试用前冻结；任一必需项缺失，复盘待补证、预约不派发。附带项允许标为未知的条件也应预先写清。当复盘合格且下午无位，先交本人复盘和可选空档。预约成功时整句交付包含同一合格复盘（版本/可访问引用）、实际日期与时段、化妆师。以收件端按号查到内容、本人有权读回为送达依据；点开、接受建议、业务满意分别计。部分通知与合并结果分别有唯一交付号。

| 情形 | 通过时能在任务、业务源及收件端查到什么 |
| --- | --- |
| 主链与相邻指令 | 主例只在复盘合格后查约目标下午，按排班权威返回的可约集合取最早；同一最早时点的任一获准化妆师均可。排班按号读回一条有效占位，即预约成立，化妆师无需接单。本人收到同一复盘、实际时间及化妆师。输入“只复盘”时只交复盘，排班查询、写入及预约通知均为 0。合格复盘须经本人收件端按交付号读回再计送达；送达未知时保留待核，只凭原号核实。 |
| 跟播实际发生与漏跟 | 同场两次开播事件只产生一次直播中跟进。能从原场次查到重点、执行者或接手状态、期间观察的时间点/来源及与下播数据的汇合。对照样本只提供事后汇总或未接手记录，不能把该分项记为已跟播；若缺的是本次必需依据，预约不派发。 |
| 两位主播与跨夜续办 | 同一运营同时有权跟两人，模型上下文、引用、交付只包含各自相关场次。离开 App 后等待继续，回来显示原任务与原目标日期。已确认开播时间变动，同一场按新开播更新跟播和依赖安排；若要改变已绑定的预约日期或已有占位，展示影响并按新的明确指令办理。 |
| 满位与候选失效 | 下午全满，预约有效数 0，本人先收到合格复盘与带日期、时段、化妆师的真实可选项。运营选后再次核权和查位，从原任务续办；所选档刚被占就刷新可选项。没有其他空档时如实显示，等待运营决定。不得擅自替换到另一天。 |
| 并发占位与改期 | 两项不同任务同时看到同一化妆师同一时段，排班只接受一条有效预约；失败一方在本次授权和原下午范围内重查下一最早档，无档走满位分支。改到已被占的档时，排班读回原预约仍有效、新档无本人的新增占位。测试交叉核对两个任务和同一排班资源。 |
| 回执丢失、重启与迟到 | 制造排班已收/已占、产品未记回执的窗口，凭原操作号查单。逐次登记实际请求到达、有效占位、计费（如适用）、本人收件。未知期间不重发写入、不释放预留、不宣称约好。重复/错误/迟到回执不驱动第二次交付。权限仍有效且查实后只续一次；失权/已取消仅允许按独立获准的对账权限核账。 |
| 原任务改主意 | 等待下播时补充“妆造不用约了，复盘照做”，更新目标版本，只取消预约子项，复盘继续。改口与写入竞态按排班回执或查单划界。已经生效时，向仍有权者说明实际时段及化妆师；如需撤销，单独核实取消权限和业务回执。结果未知时先待核，不宣告未约或已取消。 |
| 人工跟进冲突与交接 | 同一运营同时需要人工跟两位主播，显示场次、重叠区间与受影响事项，由运营选择优先级。仅能交给当前有权接手者；持久区分已发起、已接手和工作已完成，未接手不能记作完成。按原/新运营的当前权限分别核对能查看和接收的内容，失败有明确状态。 |
| 缺证、更正、撤权 | 设置开场有片段、仅汇总、资料错场/被更正、在读取后外发前或交付前撤权。复盘逐项与实际证据一致，错场与旧撤回资料不会出现在模型、报告或可兑换链接；必须项缺证时预约写入为 0。已合法送达的历史保留事实，随后读回独立核权。 |

**业务验收与准入。** 产品负责人、实际跟播运营、场次数据负责人和排班负责人在 MVP 实施方案复审前明确首批试用对象/源、跟播证据类型与必需项、下午边界、预约与收件接口、可查单机制、改约/取消主体，以及同一主播可否同时占多个时段。未决定的动作规则应先关闭相应入口，再交业务裁定；核心主链若无法取得可靠来源或真实占位接口，列为实施阻断。接入隔离测试租户后验证竞争/故障；业务试用仅在批准的真实授权场次及可操作的排班范围进行。

业务试用前锁定样本、正常/异常覆盖、权威参考、现行人工流程和可接受标准。逐场记录分母、复盘事实/引用正确性、运营能否指出下一步及接受/退回理由、人工与试用耗时和返工原因；预约核对条件、排班实际有效数、重复占位和收件内容。分别报告复盘、预约、整句各自适用的分母；条件分支按运营原意判断，约满待选期间仅记部分完成。测试用户退出 App 不计放弃。实际用户判断、真实预约、节省时间及成本均待实测。
