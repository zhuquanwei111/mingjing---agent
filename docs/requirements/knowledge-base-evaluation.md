# 知识库选型的证据、实验与验收

本页衔接[五层分类与技术候选](../designs/knowledge-base-selection.md)、[机构资料与维护](../designs/knowledge-base-materials.md)和[员工原话校准题](knowledge-base-conversations.md)。公开实操报告、明镜隔离小样本、明镜岗位试用是三类不同的证据。下述比较与验收是提案，尚无完整引擎在明镜业务上的胜出结论。

## 其他团队用过之后，哪些经验值得带进测试

| 来源性质 | 实际看到什么 | 在明镜的题里怎样检查 |
| --- | --- | --- |
| Block 的工程师介绍其生产工作流升级 | 运行中的旧流程要和新版本分流。 | 策展、授权和资料更新跨夜；在途入库任务与新任务使用不同构建时，检查旧任务是否让旧索引重新生效。[Block 工程师分享](https://pages.temporal.io/webinar-r2r-upgrading-payment-workflows.html) |
| 复旦大学、宁波大学附属第一医院等团队的 RAGFlow 应用研究 | 对表现最佳配置做了 20 名患者及照护者的可用性试验。加检索后部分模型的易懂程度略降。比较项是三种模型加入检索前后。 | 让实际岗位判答案能否用自己的话讲明白，也单列准确性。该研究能支持列入候选，无法给出与 Docling 组合的优劣排序。[原研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC13309650/) · [方法与结果](https://pubmed.ncbi.nlm.nih.gov/42369998/) |
| MITRE 研究者的原表对照 | 在一份复杂安排表上，Docling 有相邻列误合并、勾选标记未对准表头等问题。 | 准备报价表、排期和脚注，逐个核项目、日期、行列和单位。单一外部样本的结果不推广为全部格式的排名。[原表与输出](https://www.level11.ai/static/Extracting%20the%20SoA.pdf) |
| Clarvo 招聘匹配的生产复盘 | 多条件查询几乎没有使用向量索引，复杂查询一度超时。优化查询后，其工作负载从最高数十秒降至个位数毫秒。 | 附租户、客户、项目、角色和有效期过滤再测召回与延迟；核执行计划。外部耗时不作为明镜承诺。[团队工程复盘](https://www.clarvo.ai/blog/optimizing-filtered-vector-queries-from-tens-of-seconds-to-single-digit-milliseconds-in-postgresql) |

## 明镜已有的隔离读数

以下为 2026-11-24 已有隔离实验的脱敏摘要，原始报告由项目方保管。本专题没有重跑它们。资料规模、授权主体、使用端点和实际结果须随每项结论一起阅读。

| 试验 | 已确认的结果 | 留下的问题 |
| --- | --- | --- |
| 旧 P2 产品层，合成身份、真实 PG、Temporal 与磁盘文件 | 32 个既有回归通过；三份文件重启后摘要一致；跨租户互读 404，撤权后旧引用 403。 | 以两个任务登记同一资料的不同修订，再授予权限后旧内容仍可开。要专测“资料本身已撤回”和“用户稍后恢复读权”的组合。 |
| 独立发布清单与 SQLite 检索 | 四个合成原件、八个索引段落。独立重建后 14 项断言结果一致，另做八次查询或打开。当前引用两份通过，植入的八个错误均检出。 | 合成集合由命令行指定。尚缺真实登录、实际缓存、模型收到的内容与本人收件端的联验。 |
| 同批中文资料的 PostgreSQL 子串检索和 SQLite FTS5 加短词回退 | 两条路线各通过字面查询 10/10、发布授权与重开 20/20，改写题各为 0/4。裸 FTS5 三元分词对本组一、二字查询为 0/6。 | 两路共用应用层授权；四份合成文本只能支持按号及少量原词检索。完整 RAG 的检索质量、撤回、维护与容量仍需同题比较。 |

受控读数定位：旧 P2 的 junit.xml 与 observations-r2.json、发布清单实验的 results.json 与复核结果、字面对照的 results.json（SHA-256 为 a794629f6bb2b15bff51864de98fb8b05f1da5b001942a1ea770447b1657eb4b）。项目方可按摘要核对原件。

## 选型怎样执行

| 步骤 | 投入与对照 | 须交付的证据 |
| --- | --- | --- |
| 盘点与冻结 | 收集代表性文档、原生工作表、跨页或扫描件、完整视频及剪辑版。缺少内部资料时先用有来源的公开件和合成件，分别标识。用已有文档系统或人工办法完成同一任务。 | 样本清单、原件摘要、权利与用途、适用版本、问题来源、参考位置、当前办法的用时；另列未覆盖的岗位与资料。 |
| 隔离比选 | WeKnora、RAGFlow 和可组合路线在同一套原件、身份和问题上分别跑；同一层固定其他变量。对纯关键词、向量和混合检索做对照。已有系统能直接办完的任务保留作基准。 | 每条路线的版本／镜像摘要、许可与资源、解析产物、入库时间、检索前五、模型实收证据、逐题对错、维护动作及实际成本。端点不可用就标未测，不推算胜负。 |
| 集成验证 | 在同一候选构建上联接真实宿主、受控资料源、对象授权、实际缓存、获准模型和本人接收端。 | 一次已找到原文、随后原件撤回的失败运行：旧引用后续使用受阻、业务与收件无新增效果、排障者只凭任务号定位、离线评测独立检出错版。再取同构建合格对照的真实原件及收据。[固定联合验收方案](https://github.com/zhuquanwei111/mingjing---agent/blob/210a24f240c73e86746e608907242a200fc94cc0/docs/designs/whole-product-phased-implementation.md) |
| 岗位试用与决定 | 运营、编导、经纪、商务和职能岗位用获准内部资料做实际工作；同类任务分别用现有办法和候选完成，交叉安排顺序以减轻熟练度影响。 | 按岗位看完成率、回答易懂程度、用时、返工、错用旧版和是否能交付；写明采用哪些层、哪些格式限用、哪个候选淘汰及原因。允许“证据不足，保留两案”的结论。 |

## 比“搜得到”更严格的验收

| 验什么 | 如何构造反差 | 如何判 |
| --- | --- | --- |
| 口语任务和分轮理解 | 七个范围做独立盲题，混入口误、俗称、项目重名、附件指代、跨午夜和先问后改口；一半能答、一半缺证的同一问题照常出。 | 按[逐轮评分约定](knowledge-base-conversations.md)分别核证据排位、答案、合理澄清和任务完成。公开题及其换名版排除在成绩外。业务确认分母与目标后冻结。 |
| 关键事实与使用权 | 相邻行金额相似、单位不同；两个相似项目用过同一首歌；旧授权允许线上发布，当前员工想线下商用。 | 预先列为关键的主体、金额、生效时间、许可范围或版本，答错一项即不放行相应场景。能明确指出哪个环节缺证。 |
| 撤权、衍生物和重开 | 两租户、同租户不同项目；先合法搜索、生成摘要或交付受控链接，再撤权或撤回原件，最后重登及恢复用户读权。 | 权威变更先发生时，新的标题、摘要、正文、模型输入、原件、交付均无越权内容。对先发生的合法交接单独记时序；已下载副本与系统能拦住的后续取用分别报告。 |
| 换版、幂等与恢复 | 反复推相同版本；重建索引时发布新条款，一份下游培训手册仍引用旧版。中断解析、恢复进程并把备份还原到隔离实例。 | 重复正式发布为零；旧任务不会复活旧索引与权限；受影响手册可列出。区分“当时有效”与“现在有效”。记录恢复耗时、实际恢复点和残留缺口。 |
| 多模态依据 | 同一段台词的两版剪辑，或 OCR 文字相同但表头、脚注不同。 | 回答能打开正确版本的页、单元格或时段，并区分听见、看见和推断。只有字幕时，对画面问题说清缺证据。 |
| 负载、成本与运营收益 | 查询期间持续入库、换版及撤回；分开测交互检索、生成和后台解析。4 核、8 GiB 的开发环境只生成该环境的实际记录。 | 分别报 P50／P95、错误、排队、CPU／内存、每千页解析和每百问成本、人工更正与维护时间，附页型、问题数和硬件。试用峰值由实际工作记录确定；生产容量和上线日期待目标环境实测与业务决定。 |

## 让失败可复核

以“旧合同还搜得到，客户现在到底能不能投”为例，评阅人先固定今天的权威合同、旧条款和员工可见范围，再分轮提出日常问法。记录查询时刻、资料版本、候选返回位置、实际送给模型的段落、最终答案及引用。若系统找对条款却混淆“可预览”和“可投放”，归入回答错误；若旧版在撤回后仍被送出，归入授权或版本硬失败；若连可用条款也搜不到，归入检索遗漏。每次修复重跑原题和相邻负例，用原收据验证效果。

每次裁决保留一份记录：问题和资料版本、控制变量、失败样本、是否复现、硬门槛结果、成本／工时、适用边界、责任人、评审意见与日期。没有实际票据的成本标估算或未知。完整引擎和正式宿主的空白项保持待验证，独立审查和批准分别留痕。
