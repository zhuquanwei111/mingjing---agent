# 明镜全机构身份与权限需求文档

**第一轮需求评审稿，待项目方确认。** 员工问：“我今天替小林盯晴禾，昨天她能发的那版，我也能发吗？”明镜应当能答到这一步：谁已经确认你接班，你现在能看哪一版、能替谁办哪件事，客户从哪里能收到。若还缺发件授权，你能找到负责确认的人，客户收件处仍是空的。

## 六种日常工作怎样算办成

| 情形 | 谁要办什么 | 从当事人的位置验收 |
| --- | --- | --- |
| 入职 | 人事确认小周入职哪家机构、何日生效，主管安排岗位，项目负责人把她列入晴禾项目，资料负责人按职责开放当期可读版本。 | 小周用本人账号进入正确机构，能办分配给她的事。生效前、同名的另一机构账号、尚未加入的项目，从搜索、通知和旧链接均看不到对应客户资料。 |
| 跨部门协作 | 编导请剪辑修订晴禾片尾，运营约化妆师。各资源负责人分别决定可改哪版、可看谁的空档、可替哪位主播预约、改期或取消。 | 剪辑能回交修订件，无法借此发给客户或读底价。只获准查空档的运营能看到可约时段；试着代约时收到权限提示。排班方查单为零、化妆师未收到预约通知。有代约权时，排班方才可受理同一请求并给出真实单号。 |
| 临时替岗 | 小林请小周接半天班，项目负责人确认起止时间和交接事项。小周用本人身份接手，资料预览和对外发件分别确认。 | 两人都能看到已交接事项、截止时间和待办人。提前结束或到期后，小周重开项目链接或恢复排队任务都按当时权限办理。案例见下节。 |
| 跨客户复用 | 商务拿晴禾项目作参考，另一客户青荷想看。合同或授权负责人核实是否存在可向青荷展示的版本及渠道，交付方核收件人。 | 只获准看通用案例时，青荷只能收到通用版。没有适用版本时停在申请环节，青荷的搜索、转发链接、预览和通知均不透露晴禾标题、封面、片段或报价。 |
| 调岗、离职 | 人事记录转岗或离职生效时间，原主管清点未交件、旧链接和在途预约，新负责人指派有权的人接办。各业务方核哪些权限应收回、哪些独立授权仍有效。 | 调岗人从旧会话再次办理原岗位事项会被拒，新岗按新分工办理。离职生效后本人及依赖其委托的任务停止新使用。接任者以本人授权接单，仍能区分前任已交、待核、未办的事项；历史经办人可追溯。 |
| 智能体受托执行中撤权 | 小周委托智能体稍后交件。任务要记清谁委托、为哪个机构与项目、可用哪些资料、准做哪些动作。小周撤回委托、失去对象权或资料许可改变时，剩余步骤分别复核。 | 员工能看到停在哪一步、已经发生什么、由谁续办。任务连续运行、暂停恢复或重试均遵守当前限制。另派人接办时须取得新委托；已生效的交付或预约按原号查询，避免重复发送或占位。 |

**机构、项目与人分别核对。** 这里的租户指本次办理所处的机构授权范围。一个机构可服务多个客户，一个客户可有多个项目。同一员工若受两家机构委任，切换机构后须以目标机构的身份关系重新取权。验收用两个机构的同名项目，再用同一机构内的晴禾、青荷做对照。用本人账号、外部协作者账号、客户账号和受托智能体分别办理。再用小周本人登录做两次独立核对。先保持机构不变，在任务中自称是有发件权的小林。再保持小周姓名不变，声称代表一个未授权给她的机构。两次都应按已验证身份和实际委托关系拒绝，资源端无越权读取，收件端没有新增交付。

有核查权限的人能按任务号追溯委托人、实际经办人、资源版本、决定、时间和结果。普通员工得到与自身有关的原因及办理入口，未获准的资源细节保持隐藏。

## 晴禾交件，从小林交班到小周交回

沿用知识库专题中的晴禾春季项目、蓝背景片尾、指定客户版和晴禾自有账号自然发布许可。教学版另有班级及用途限制。知识库负责人回答“哪一版、原件在哪、条款覆盖什么”；本专题回答“今天谁能用它做什么、何时失效、对方实际收到了什么”。小林、小周、班次和以下授权均为评审示例。[PR #23 固定版本的原场景](https://github.com/zhuquanwei111/mingjing---agent/blob/43b6f2384bd8d9afc54ec0f0bda26fb9117a1d25/docs/requirements/knowledge-base-requirements.md#L58-L86)

| 发生的事 | 谁有权决定，哪套业务记录作数 | 当事人看到什么 |
| --- | --- | --- |
| 1. 小林提出交班，小周确认接手 | 人员名册确认两人在本机构有效。示例中项目负责人有权批准当天 09:00–17:00 的替岗，在项目交接记录注明晴禾项目、小周和事项。资料方在对象授权记录开放指定客户版预览。 | 小周以本人账号看到本项目及可预览版本。小林发来的旧链接仍按打开者本人核权。点“交给客户”提示尚缺发件权和申请入口。 |
| 2. 小周申请发给晴禾 | 合同负责人依据有效条款确认版本、客户、渠道、用途和期限。有权批准本项目对外交件的负责人核实小周的替岗范围，在交付系统登记仅向晴禾指定收件处交此版本的资格和截止时间。 | 小周看到获准的版本、动作、收件处和期限。“给青荷也看一眼”“买推广”需要另办。预览或获批本身没有产生交件。 |
| 3. 小周要求交件 | 小周明确发件或限权委托智能体。明镜的任务记录保存委托人、经办身份和受理结果。实际交付服务按本资源当前权限独立决定能否交出，收件方记录交付号、版本和收件身份。 | 晴禾指定收件人从自己的入口打开正确版本。小周能区分“已发出，送达待核”“已送达，待客户确认”和有本人确认记录的结果。仅有发件草稿时仍显示未发。 |
| 4. 小林提前回来，小周还有待发任务 | 项目负责人在交接记录提前结束替岗。以该替岗为依据的预览与发件权随之失效。到 17:00 自然结束也应取得同样结果。小林接回剩余工作时以自己的现权办理。 | 小周原来打开的页面再取片、翻页、从收藏或旧对话重开，都取不到受限内容。尚未交给外部的任务停在“替岗已结束”；收件处没有新增。小周能查本人交接状态，可见详情随当前权限收回。 |
| 5. 核对刚才那笔是否赶在撤权前发出 | 有对账权的经办人凭原交付号从交付和收件系统核对。在途且暂缺回执时登记待核。若已合法交付，交付事实保留。每次重新取件都核收件人资格、版本是否仍有效及当时的用途和期限。 | 仅小周结束替岗，晴禾仍可依有效许可打开客户版。即使收件人账号有效，一旦合同到期、指定版本停用或对应许可撤回，旧链接再取件即被拒。已下载副本由商务通知停用、追回执并登记未确认者。小周的替岗结束也不影响独立获准的教学班。 |

核验交接先后时，用同一笔待发交件做两次独立验证。第一遍，交付服务已经初步放行，资料字节或可兑换引用还没交出，此时让撤权生效，再放行待发环节。收件端新增须为零。第二遍，先让受控收件端取得该版本，再撤权并放回执，原交付号只有一次实际交接。用同一交付号关联权威撤权记录与首次不可撤回交接的先后证据，回执另记送达状态。还有一种情况要从客户的播放器核对：首段已经播放时，撤回该收件人的观看许可。已经收到的首段保留，资料服务此后仍控制的分片不再送达。

若发件人说“发给客户”却没有明确收件人或渠道，系统只追问缺的条件。项目负责人能派班，合同负责人能解释许可，只有拥有对应对象授撤权的业务方能授予或收回动作。以上名册、交接、授权、条款、交付和收件系统均按其保存的事实命名。需求确认时请为每项填入明镜实际系统及可确认的责任人。

## 撤权发生在半路，怎样验到真实结果

在已获准的测试环境中，用同一场景各走一次**已读后暂停再恢复**和**已读后持续运行**。两种情况下都分别把撤权放在下列五步之前，用有权时的正例作对照。表中结果是待验证要求。

| 下一步 | 在哪里看撤权后的结果 |
| --- | --- |
| 再读资料 | 在资料服务、员工浏览器和旧会话重开处核对。新取回的受限正文、摘要、缩略图及可用下载入口均为零，缓存命中也须满足。 |
| 把已读上下文发给模型 | 让已读资料含一笔合成报价，撤权前先将它写进摘要。逐次核对受控模型端实收的请求，受限原文、可兑换引用以及摘要中转述的该笔报价均未传入。 |
| 把参数交给工具或下一级智能体 | 在工具接收端检查实际参数与引用。结束的委托不能借另一个执行身份继续传送受限资料。 |
| 正式提交业务动作 | 让宿主先放行，排班方在提交前收回该主播的代约权。排班方独立拒绝。按原操作号查排班方提交历史和通知记录，可以有拒绝记录，成功占位次数和预约通知数都须为零。 |
| 把结果交给收件人或凭旧链接取件 | 在指定收件处、另一客户的收件处和旧链接实际打开处核对。撤权先于首次不可撤回交接时，受限内容和可用引用新增均为零；仅生成任务状态或发出通知不能证明送达。 |

若只撤回某份资料的使用权，仍然获准且能独立完成的事项可继续。若撤回整份委托，在暂停恢复和持续运行两种情况下，都要在模型、工具和子任务接收端数出此委托新增调用、派发和启动各为零。按独立权限核对撤权前已发出的原操作，只能查单。

对五步都要问清“资料或动作何时已经交出”。如果交接先发生，则保留此前事实，阻止撤权后的下一次使用。回执丢失时由单独获准的人员按原号查证，待核期间不再发送。若实际身份或资源方失联、权限过期、不同系统的先后无法确认，受影响的受限步骤暂停，界面说明待谁核实。离职后迟到的成功回执可以补记已发生的事实，不触发向原员工的新交付。

## 项目方本轮要确认的三件事

1. **谁能授、谁能撤。** 入职与离职时间、项目成员、替岗、发件、代约、客户收件资格分别由哪个实际岗位决定，哪套系统能查到当前有效记录？有异议时由谁处理？
2. **一班到底交哪些事。** 晴禾替岗默认能否预览、能否发件、由谁批准代办？排班中查看空档、代约、改期、取消各需谁确认？请用一条日常原话或例外校正上表。
3. **到期后留给谁收尾。** 旧链接与已下载副本分别由谁处理？已在途、未送达和未发出的工作由谁查单、谁接回？员工、客户和审计人员各应看到哪些事实？
