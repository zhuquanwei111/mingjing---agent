# 长任务计划与接续

本约定用于让 Agent 在复杂工作中保留决定、说明完成边界，并在需要换会话时恢复任务。它不能保证模型不遗忘，也不是自动创建或唤醒会话的服务。来源和适配范围见[完整配置任务](tasks/codex-development-configuration.md#采用依据与适配边界)。

## 什么时候需要记录

小范围、一次可完成的修改可以在会话里给出简短计划。跨文件、涉及运行行为或持久状态、分阶段或需要交接的任务，沿用已有计划；没有记录时才创建 `docs/tasks/<task>.md`。不要为一个任务维护多份进度账。本次配置只使用[现有总账](tasks/codex-development-configuration.md)。

编辑有影响的运行行为、API、配置或持久状态前，先确定四点：必须实现的可观察行为；需要保持的已支持接口或持久状态；明确不支持的相邻情况；可以复用的现有路径。局部修复用一段话即可。范围变化时更新这段说明，不能为每个新发现无限增加兼容分支或另造通用平台。

## 记录必须足以恢复工作

不要求固定标题或大文档；在已有章节保留以下必要信息即可：

- **目标和完成信号：**用户要得到什么，哪些结果能证明完成；多阶段任务保留完整范围。
- **范围和授权：**已接受的决定、明确不做的事项、已获得的交付授权及仍需用户决定的边界。
- **代码状态：**已核实的分支与基线或候选提交，当前任务拥有的未提交修改、相关路径和 PR。
- **进展与理由：**已完成、未完成、关键取舍，以及已失败或排除的路线和依据。
- **验证：**具体提交或未提交候选、环境、检查结果与证据链接；未运行和失败如实标记。
- **下一步：**可以直接执行的首个动作；有阻断时写清缺少的条件和推荐处理。

记录中的提交是已核实的基线或候选，不要求文件自引用包含自身的新提交。新会话必须重新核对当前 HEAD 和工作区。密钥、运行凭据、完整聊天和大段原始日志不写入计划，引用必要的受控证据即可。

## 连续推进与收尾

同一连贯目标继续当前会话。阶段完成后，按既有授权推进总任务剩余工作；不得把一批改动完成当作整体完成，也不要为普通修复、复验、提交或已授权 PR 再次等待“继续”。每次真实暂停前更新记录。

目标及适用交付完成时，明确报告“本任务完成”，说明结果、实际验证、提交或 PR、剩余限制。待人工合并时说明 Agent 已完成的交付与用户保留的决定。存在真实阻断时报告该阻断和恢复动作，不能把尚待验证写成完成。

新的独立目标适合新会话。当前目标尚未完成但需要切换会话或环境时，先保存上述恢复信息，再给出包含项目根目录、任务记录路径、当前状态与首个动作的简短接续说明。换会话不是清除未完成责任：后续继续同一目标和授权范围。

不要仅凭固定 token 比例、发生压缩、重复提问或两次失败断言必须换会话。先对照实际代码和任务记录，定位偏离或阻断；无法可靠恢复当前目标时再建议保存交接并切换。

## 新会话如何恢复

1. 读取根 [AGENTS.md](../AGENTS.md)及其要求的工程规则，再读取指定任务记录。
2. 由 Agent 执行 `python3 scripts/check_development_docs.py --status --task docs/tasks/<task>.md`，核对实际根目录、分支、HEAD 和未提交修改。命令只读，不会同步远端或启动服务；需要最新远端状态时另外核实。
3. 对照计划与代码、PR、CI。区分当前候选和历史报告，保留其他任务的修改；有差异先修正任务判断，不把旧记录当成当前事实。
4. 用简短说明确认目标、已接受决定、实际进度、剩余事项和下一步，然后继续已经授权的工作。缺少具体决定才提问，不要求用户重述整段历史。

接续验收看新会话是否准确恢复并执行正确的下一步；引用检查通过或计划文件存在，只能证明入口可找到。用户不需要在终端手工准备交接包。
