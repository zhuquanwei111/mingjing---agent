# AGENTS.md — Codex 项目执行规则

本文件对仓库中的所有 Codex 工程工作生效。

## 不可违反的原则
- 不按当前业务、岗位或 Agent 数量固定平台结构。
- 普通程序、工作流、Agent Loop、外部服务拥有独立实现自由，通过稳定的 Capability 契约接入。
- App/API 和工作流不必通过 LLM 才能调用确定性能力。
- 能力注册、发布、授权分别处理；发现工具不代表获得调用权限。
- 不把 Temporal Event History、LangGraph 检查点、产品 Task、业务写入收据混为一个状态。
- Temporal Activity 可能至少执行一次；业务副作用的幂等与结果确认必须由可信执行边界保障。
- 不将模型生成的工具调用、审批记录或旧权限快照视为当前执行授权。
- 不把所有缺口都从零自研；优先复用经过核验的公开接口和成熟组件。
- 不为每项逻辑职责建立一个微服务，也不同时引入两个顶层持久化调度器。
- 不 fork Temporal 或 LangGraph，除非最小验证证明公开扩展点不足，且得到明确批准。
- 不将任何调研报告中的示例代码视为已通过安全审查或可直接用于生产。

## 阶段门禁
P0：只读核验仓库、依赖、许可证、版本和最小代码入口，产出记录。
P1：建立隔离、可丢弃的 Walking Skeleton，验证异构能力、故障、撤权、预算及版本升级。
P2：P1 验收通过并获得确认后，建设最小自有公共层。
P3：根据真实需求扩展治理组件与业务能力。
任何阶段失败，先提交失败证据和替代方案，不绕过门禁继续建设。

## 安全要求
- 所有敏感写操作在实际 I/O 前重新检查当前身份、租户、资源和动作权限。
- 任何缺失、失效、不可达的关键授权/发布/预算门禁均不得默认放行。
- 对不支持幂等和结果查询的外部副作用，超时结果未知时禁止盲目重试。
- 业务审计与收据必须可靠持久化，不能仅依赖可采样遥测。
- 测试只用合成数据和隔离服务；密钥不进入代码、日志、历史或模型上下文。
- 取消不能被描述为已发生的外部副作用自动撤销。
- 不把自动补偿当成普遍可逆能力。

## 编码规则
- 使用类型标注、结构化错误、版本化 Schema 和可重复运行的测试。
- 固定依赖与容器镜像摘要前须检查兼容性和许可证；禁止未经审核的浮动生产镜像。
- 统一记录 task_id、run_id、workflow_id、operation_id、attempt_id、artifact_id 及关联关系。
- 能力 SDK 不应暴露 Temporal/LangGraph 内部细节给普通业务开发者。
- 对第三方组件采用适配器，避免侵入上游核心。
- 每次提交说明新增文件、变更原因、测试结果、未验证事项和回滚路径。
- 无真实测量不得宣称性能指标、代码行数、人天、零超支或生产可靠性。

## 何时停止并报告
- 许可证或可取得性存在阻断。
- 官方集成无法完成必需的恢复粒度。
- 业务写入发生重复副作用或无法确认结果。
- 撤权后仍可执行敏感操作。
- 子任务或重试绕过预算、工具范围和取消约束。
- 为接入新能力必须大规模修改运行器核心。
- 生产环境、外部付费服务或敏感数据将被触及而尚未获授权。
