# 补测预注册 · 两个相邻故障窗口

冻结基线为 #12 的代码 90946305a8f16c74e8603a8f2974831ec7590d1c、原始档案 554367bf8528a9500a88bac4033ad15a5983b4de。新增试验与 CI，原试验、原始档案、正式目录均保留。只在独立 Compose project、Temporal namespace、PG 数据库、独立模拟 HTTP 收端测试。模型收端没有任何供应商账户。不得用 SDK 次数、任务总额度、数据库最终行数推断实际派发。每次模型 HTTP 到达逐笔收费，每次工具提交逐笔收费，交付收端记录全部请求。计价单位均为模拟单位。

## 事前判据

1. 首轮故障。先使两个首轮真实 Pydantic AI 请求到达收端，模型分别生成回复并按 HTTP 请求收费，然后把回复扣在收端。确认无产品 checkpoint、无工具请求，再 SIGKILL 活动 worker，由真实 Temporal 在另一 PID 上重试同一 workflow/run/activity，尝试号 1→2。两条路径对照。
   - 旧 task 计数路径：重试仍有第二个槽，同一个产品操作同一个首轮实际到达 2、费用 2。第二次同样不提供可用回复，工具发/效/费、交付均 0。若没有观测到重复，对照不能支持改造必要性。
   - 治理路径：在产品 PG 中先以不可变 operation + round 唯一声明和稳定 dispatch ID 领取模型轮，事务提交后才可发送，HTTP 记录关联该 ID。重试、多进程重复复入均不可再发；首轮实际到达/费 1/1，模型未知的预留保留、无 checkpoint，无工具/交付。另一个活 worker 必须实际接到相同 operation/round 的复入，用物理 PID、保留的唯一声明与独立收端计数核实。不得把多个 round 的 task 总计冒充轮级保护。
2. 晚到工具回执。活跃和撤权两例均以真的 Pydantic deferred tool 调用先完成第一模型轮，用产品 PG 保存受限消息、原工具调用 ID、会话及工具操作。HTTP 工具异步生效、收费，真实查单先返回未知，原 Temporal 工作流保持运行，工具预留 3、实付 0。然后打开查单并对每例重复通知两次，保留原工作流。通知无权自行创造业务事实，两次都实际查原工具 operation。
   - 活跃有权：同一工具操作总发/效/费 1/1/1；领取唯一第二轮，真实 Pydantic 用原工具 ID、同一 conversation、正确回执接续，模型各轮 HTTP 收费各 1，总数 2。交付收端 1，工具结算一次，最终 held/spent=0/1。单纯永远挂起判失败。
   - 先撤权：两次迟到只结算一次，工具 held/spent=0/1，无第二轮声明或模型请求、无交付；总发/效/费 1/1/1，模型只收首轮费 1。冻结 #12 的取消、错配、旧版隔离、未知等原用例须在新 head 继续通过。
3. CI 收集独立端逐次 HTTP 内容与模型收费行、工具到达/效果/收费、交付、产品授权/轮次/预留/结算变化、真实 PID 和尝试，以及所有对应 Temporal 原始历史。对所有事件中的 payload 解码，断言无提示标记、工具 ID、回执或模型/工具受限内容。按 tested head、依赖锁、环境身份和 SHA-256 重算档案。任一必要对照或断言未验证都不能记通过。首轮对照以真实收端信号定位故障，活跃/撤权以产品与收端共同定位，不能仅靠 sleep。

## 对整栈结论的影响

两窗和冻结回归全部通过，保留 Temporal 的持久协调/重入与 Pydantic AI 的运行时工具契约、消息编解码和续轮；保留产品 PG 负责轮次唯一声明、待核、授权、结算和交付资格，独立收端事实校验。不能把模型未知自动恢复宣称为框架自带。若安全阈值任一失败，B 的正向推荐冻结，定位到协调、SDK 配对或产品账本分别整改；若活跃授权后不能推进或恢复 ID/会话失真，不接受以永远待核保安全的方案。旧路径没有真重复则无权以该对照支持去留。即使通过，声明后发前崩溃、模型没有查单权、交付发送后的回执歧义、撤权与已获准在途请求竞态仍需单独设计。此试验不启动 W0/MVP。
