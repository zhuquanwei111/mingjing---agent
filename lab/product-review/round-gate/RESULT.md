## 收端与产品账

- 两条首轮故障用相同模型请求正文，旧对照直接调用原 worker 的 agent_for / charge_model_slot。旧模型无轮级产品派发 ID，由相同任务和实际首轮消息对账。接收端将每个 HTTP 模型请求和一笔费一起提交，再阻塞回复。控制器确认两条都已收费、产品都没有 checkpoint，杀死 PID 13（退出 -9）。同一工作流运行及 Activity 1 的第二次尝试由 PID 35 执行。旧模型再次实际收到首轮、两次均未能取得回复。治理模型只有一笔，PID 14 在原进程仍在等待和已转未知后各执行一次重复入口，均被同一声明拦住。收端已收费与产品尚无权确认费用是两种独立事实。
- 晚到两例在独立收端先发生工具效果、记费，再放行工具提交应答，随后首次查单都未知。原工作流仍在运行，工具 held=3、spent=0，首轮模型已核销。冻结 #12 还单独覆盖先接受异步任务、之后才生效的次序。
- 打开可见性后，每个原工作流收到两个独立通知，PID 35 和 14 分别同步查同一工具操作。释放前两次查询均读到可确认结果、尚无产品结算。释放后两例各发生一次新增结算，一次重复核对。活跃例在 PG 唯一抢占二轮，沿用 checkpoint 内原工具调用、同一 conversation、不同 SDK run，通过实际模型 HTTP 收端接续并交付一次；撤权例未声明第二轮。工具费用与每轮模型费用独立记账。
- 三个 Linux worker 进程、独立产品与收端数据库、专用 Temporal namespace、禁外联的 Compose 网络。合成受限内容可在产品库、独立收端和试验原始档案核查。六份真实历史的 44 份 payload 经逐项解码检查，未见本次设定的请求标记、工具名、调用 ID、回执与模型消息内容。此结论只覆盖指定标记及 Temporal 历史。
