## 权限源和不可撤回边界

| 出口 | 当前权限与最终判定的拟定责任 | 首次不可撤回点与实宿主待查事实 |
| --- | --- | --- |
| 业务或资料读取 | App 身份映射主体租户，业务数据服务或资料发布服务核资源、操作和当前版本 | 放行结果字节或可兑换引用前核权。真实服务 ACL、缓存及引用的二次打开须验。 |
| 模型外发 | 身份/资料权威给出动作范围，可控模型网关在实际传输前终核，禁 SDK 隐式重发 | 受限数据首次交给不可撤回的外部传输端。鉴权失联、过期凭证及长连接复用须验。 |
| 工具与委派外发 | 网关终核本次发送，接收业务服务对本资源独立授权。任意脚本无直接受限凭据。 | 向工具实际交出参数、可读取的上下文或引用。两权威跨域时只允许已被业务方认可并能排序的协议。 |
| 正式写入 | 业务服务拥有对象 ACL 和写入事务，当前授权及唯一操作号在可信事务边界判定 | 正式写入的提交点。在途已生效留账，撤权后停止未交接步骤。 |
| 正式交付 | 交付方核对象、收件身份与任务质量，资料服务负责受控引用兑换 | 首个收件端能获取字节/有效引用的时点。交付回执和二次取件各验。 |

这些是目标责任，现有输入未给可核对的正式 App IAM 接口或各实际服务的提交/授权实现。#11 证明共同受控授权域的机制；普通 HTTP 出站与远端写入是不同不可撤回点。跨权威如果实际服务不能终核，关闭相应受限出口或改为接收端参与的授权协议。若该出口是必需且无法替换，W0 的该项失败将迫使调整公共授权/业务服务边界。

## 会改变采纳决定的缺口、实验与改判条件

1. **动态中断、异步契约和在途版本（G04/05/07/14/15/19）。** #5 的工具给即时 Output，Agent 整段 Activity 不重入。取一个以收据结束的合成外部异步能力，叠加一个工具回合中断，即可同时检验两个缺口。受理、效果、可查回执与正式交付可分别观测。用 Pydantic AI 固定版的公开延迟工具/消息接口保存工具请求与稳定调用 ID，Temporal 固定操作号分派，实际独立接收方提交效果和模拟费用后、结果回写前强杀 Worker。新进程读取旧版本消息，按同一操作号查证，使用原调用 ID 回传并完成下一模型轮。模拟重上新宿主代码时检测可读版本与不支持的版本，保留旧记录。已知且有权时只发一次、效果一、模拟费用一、收据与原调用正确配对、交付一次；状态未知时不重发，预算保留、下一模型请求和下游交付为零增量；取消后可信结果只结算；不兼容旧数据不得按新语义推进。必须观察真实服务端迟到/未知、进程和引擎重入历史，分列请求和收费。需区分已保存的版本规则与实际 SDK/部署滚动升级。可与只读比较或刻意失效的对照交叉核验。若 SDK 无法按原 ID 安全返回或拒绝，则改轮次检查点/Agent 适配层并复核。若稳定已提交操作不能由引擎重入而不重发，改派发粒度/操作账本；仍失败则重审 Temporal 或 B。若新的异步能力只能硬编码进通用核心，则调整能力契约，记录新增公共代码；这个实验本身也不能替代 AC-17 的未来未知样本。
2. **真实宿主的双向核权与原子启动（G01/13/15/16/17/18）。** 对照上表按事实点尽可能检查现有宿主/业务接口。第一个实际身份源、保护资源与可交付终端均缺少时，专门复造一个同源授权夹具不能回答目标问题。W0a 在同一任务重现宿主已提交意图/Temporal 启动回执丢失，以及宿主放行后业务服务独立拒绝，核出稳定唯一绑定、零越权效果、零错误交付。W0b 验受限旧上下文不能再次外发、历史和日志无受限原文。若仅某接收端失败，换适配或禁用；若必经出口、数据控制或幂等跨组件协议都无法成立，改宿主、治理网关/调度或 Agent 组件并重评。目标环境服务、数据及凭据未授权，本轮不构造其审查通过状态。
3. **完整项目与长期自研责任（G02）。** Windmill 和 Dify 的固定上游材料已证明部分能力，尚缺权限终核、可核查的外部费用终局与取消后的交付同一键贯通的基本适配依据。任何完整成熟项目已有依据证明直接或少量适配便基本符合时，须与 B 同题实测，不以先胜过 B 为入围条件。模型业务效果、供应商终局及混合生产容量在相应阶段测；若实际必选供方、合规或容量条件提前出现且与硬要求冲突，才提前重开。

### 隔离实验固定用例与计数口径

测试装置先在独立收端留下 202 受理（效果与费用均为 0），控制器再让真正的后台作业完成并写唯一回执和一笔模拟费，暂停在旧 Worker 尚未收到业务结果的位置。只在数据库同时读出“效果已提交、工具结果与终局仍空”后强杀原 PID；同一个 Temporal Workflow ID/Run ID/Activity ID 的新 attempt 由另一个进程读取旧的请求记录。以独立收端记录发送、效果、每次收费、交付及实际模型消息，两个独立数据库保留原始逐笔记录。用动态生成的调用 ID 和业务回执值断言 SDK 发回的配对；先冻结公共执行文件，再登记能力描述，披露适配与公共层真实改动。

| 用例 | 预先规定的判定（收端累计） |
| --- | --- |
| 已知、有权、兼容读旧 | 工具发 1、效果 1、模拟收费 1、交付 1、模型共 2 次。第二次请求须出现与首次调用 ID 配对的真实回执值，已明确完成不能用待核代替。 |
| 暂不可查 | 工具发 1、效果 1、收费 1，交付 0；模型只收到首轮，产品 held=3/spent=0，维持可查询待核。 |
| 取消后迟到 | 先记录上项状态，再开放权威查单，两次相同通知或核对只结算一次，held=0/spent=1；工具、模型、交付均不新增。 |
| 旧版本读取不兼容 | 旧检查点保留，明确记录版本隔离，操作若已有可信收据可核费；不按新版重解释，不新增模型、工具、交付。真实框架跨版与滚动部署另验。 |
| 错误配对负对照 | 注入错误工具调用 ID，结果必须被 SDK 或入口验证拒绝；错误配对若进入模型或交付即失败。 |
| 载荷 | 将两个仅存在于产品消息或提供方业务结果的独有合成标记与原始工具 ID，在已解码的真实 Temporal 全历史 payload 中检查；检查点/有权模型端可找到预期正文，但引擎只携带运行引用、状态。应用日志/目标检索另在 W0 验。 |

记录原能力契约字段在何处遇到边界、实验新增的一次性公共改造、登记新能力后仍需改什么。受控协议模型只验证 Agent 接口。实验既不证明任意未来执行器零公共改造，也不等于生产 IAM、真实供应商或完整 W0。
