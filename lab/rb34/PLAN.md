# RB-03 / RB-04 隔离实验协议 v1

基线为 PR #5 实验头 `bb55c843b8dd2e9ad646e982a38cda350b3df952`，受审方案为 PR #7 `a2e79d66c4496b8e9911b35cb8a719015856cffd`，对照回执 [R2](https://github.com/zhuquanwei111/mingjing---agent/pull/7#issuecomment-7100697588)。仅用一次性数据库、Temporal namespace、隔离 HTTP 合成供方、模拟计费和独立收端；不接外部模型、业务或凭据。实验针对路线 B 的实际 SDK 组合与新协议，不能计作 A/B 新一轮排名或 W0。

使用 #5 锁定的 Pydantic AI Slim 2.71.0、openai-python 3.57.0、Temporal Python SDK 1.36.1 和 PG 17.12。通过真实 SDK、真实 HTTP、Temporal Worker、产品 PostgreSQL 及独立供方账本运行。每个样本使用独立操作号。供方每次收到 POST 单独开具一笔模拟费用，按稳定操作键与输入指纹去重业务效果；交付端单独记接收。第一次 POST 必须先提交接收、效果及费用记录，再断开 TCP 且不返回回执。真实 HTTP 客户端观察到传输失败后，在异常向 SDK 传播前停住，同一数据库之外的控制进程完成产品撤权或取消事务，再释放等待。屏障不得制造网络错误、决定是否重试或改变 SDK 配置。记录控制前后的收端快照和可核验的事件顺序。

| 场景 | 收端发送 / 业务效果 / 模拟计费 / 下游交付 | 产品事实与检验 |
| --- | --- | --- |
| 正常确认 | 1 / 1 / 1 / 1 | 可用可信收据或查单结算；预留归零，实耗 1；重复核销不重扣。 |
| 默认 SDK，首次回执丢失后撤权 / 取消，各一例 | 2 / 1 / 2 / 0 | 保留默认内部重试，仅作可重复的负对照。控制前为 1/1/1/0，第二次接收必须发生于控制提交后；业务去重未去除第二笔模拟费用。 |
| 关闭 SDK 自动重试，首次回执丢失后撤权 / 取消，各一例 | 1 / 1 / 1 / 0 | 指定 Temporal Activity 再次调度，查不到可信终局时仍为 unknown，预留 3、实耗未核销；禁止使用 POST 主动试探。 |
| 关闭 SDK 自动重试，控制发生后收到可信迟到事实，撤权 / 取消各一例 | 1 / 1 / 1 / 0 | 初始未知保留 3；以独立只读查单/可信回执查证后核销为 1，重复通知不再核销、不能交付。 |
| 只有幂等键且任务仍有效 | 1 / 1 / 1 / 0 | 以真实重入检验未知语义，未有权威终局或可信回执，保留预留，不用同键重提。 |

试验须同时保存每次真实接收的事件与请求指纹、效果和费用事件、独立下游回执、产品费用/预留状态、权限或取消变更、Activity 尝试、Temporal 历史、代码/环境版本及退出状态。任一预期无法证实则该场景失败；即使负对照复现预期，也只说明默认配置存在风险。测试运行新建的 PR 指向 #5 实验分支；结果交回 #7，W0、MVP 和真实流量均暂停。
