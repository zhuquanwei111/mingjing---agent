# 首次授权交接的隔离试验

仅针对 v0.4.1 FR-32、AC-13 的相邻窗口。待证决定是在候选的受控、同一授权域出口中，可以在撤权与不可撤回交接之间给出可审计的顺序。失败则停用该实现、修订出口或重选其组件。已有 #5 的五处动作屏障和 #10 的丢回执后重试均未测首次交接的争用。本试验不接外部模型/客户数据、不修改正式服务。

一次性 Linux、真实 PostgreSQL 17.12 与真实 TCP 收端。用一个受测授权域和每个样本独立操作号。收端为独立进程，事前不知道预期；只按真正读到的合成业务帧记录，并可延迟回执。授权表是实验内的权威身份源。发送者短事务读取当前许可并锁定至有界的网络写入交接；撤权者独立连接更新同一行。连接建立不携带业务帧，授权检查先于首次业务字节。回执等待在释放锁后进行。通过数据库报告的真实阻塞关系形成两个顺序；屏障只能控制时机，不替任一方决定准入。记录各连接的后台 PID、阻塞关系、事务回执、实际接收到的操作号及最终时间/状态；看不到预定争用即判无效。

在模型参数发送、受控工具、正式提交、结果交付四类出口标签上各运行三种确定性顺序。撤权事务持行锁时发送者尝试领取许可，观察真实阻塞，提交撤权后应为零帧。发送者先取得权威许可，撤权被锁等待，释放发送者完成一次有界交接，撤权必须在收端故意扣住回执期间仍成功提交；本次已发一次不可被登记为零。采用无锁的旧快照作负对照：取得旧许可后完成撤权，再交接合成帧，应能由独立收端检出一笔错误放行。四标签复用同一网关原语；不能外推为四个真实适配器或分布式身份源均已验收。试验未测网络分区或数据库会话失效；若实际出口无法证实单一权威顺序，关闭该受限路径，W0 设计只用可控制的合成内部执行，按实际风险另验收。

收端逐连接排空到 EOF，记录业务字节数、完整帧数及所有原始字节摘要。撤权先行必须为 0 字节；交接先行和旧快照对照均须精确等于一次期望帧。丢失任一侧见证即为无效，部分写入不能按未发送处理。
