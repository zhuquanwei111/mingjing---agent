# 已知可恢复样本的引用对照

首轮默认配置的 PG 原生队列和框架运行表含原参数、原工具号与回执；保留为阳性对照。并行增加一次同样的真实 AgentOS 原生排队、旧进程强杀、独立收端核查及原回合继续，用产品能力入口和受控模型出口将指定合成值转换为租户/用途绑定的不透明标签。平台内部将看到代理工具调用号；模型与业务服务处的原工具调用号必须保留，并在第二轮真实模型请求中正确恢复。分别比对框架真实 pending 调用号和外部真正调用号。

门槛：发送、效果、模拟收费、交付各一次，模型两次；运行及 ticket 身份不变。两个唯一原始标记（用户/工具参数及业务回执）和模型原工具号，在原生已解码队列、原生运行/会话与框架 HTTP 读回均不得检出；对应阳性标记须在授权模型实际请求及有明确归属的产品引用表中检出。只在已知、有权情形测试此适配；其他边界和跨版本适用性不据此升级。单列自有转换逻辑、受权解析边界、票据与会话的原生行为。
