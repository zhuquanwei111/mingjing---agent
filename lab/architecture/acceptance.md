# 明镜竞争性验证 · 共同验收标准 1.1

本标准在两条路线实施或运行之前冻结。验收依据是 2026-11-21 的《明镜智能体应用通用工程架构需求说明书》v0.4.1，原件 SHA-256 为 75ac634a98393b5f99fb28901a6a91bc7431290143b6458bbf1f9a2af5f23062。实验按 A → 保存 A 的结果 → B → 保存 B 的结果执行。同一会话操作，双方使用相同规格的 Linux amd64 环境。实验数值是用于触发边界的夹具，不代表产品的上线指标。

## 实验边界

- A 从指定提交 fdf04240eba747a9a681a1dad627da22d4b89cdd 导出 P2。B 从空工程开始，不导入、复制或运行 P2 的 service、catalog、状态机、预算和授权代码。
- 两条路线分配不同的 checkout、Compose project、网络、卷、数据库、Temporal 服务与命名空间、Worker 队列、身份、密钥、模型服务实例、供应商模拟服务和证据目录。只共享工具协议、合成输入、验收程序、只读镜像及模型权重版本。合成供应商可模拟丢回执，但要用独立真实持久化库先提交；禁止以应用自报的发送次数作为唯一证据。
- 先实测两个隔离容器能访问本路线新建的 PostgreSQL 和引擎、持久卷在服务替换后仍能读回随机标记、另一条路线的凭据不能读本路线数据。环境只包含临时测试身份。使用同版模型、同一工具协议、采样配置、算力和步骤上限。模型请求不发送到未经授权的服务。
- 每例生成 run_id、operation_id 和高熵合成资料标记。夹具、审计、引擎 History、收端捕获、SQL 原始查询结果以同一关联键保存。记录重试、跳过和失败；历史证据不能补本轮缺项。禁止把秘密凭据或真实业务资料写入日志。

## 公共业务契约

业务任务是核验一份合成资料清单。输入含租户、主体、资源引用、固定版本、需求清单和幂等键。两个工具分别读取授权版本的清单、按清单返回项目状态。需要取证时模型自行选择工具和参数，最终输出清单版本、完成项、缺失项和证据引用。正式交付需所有必需项通过校验。测试接收方持有独立写入记录。生产环境没有任何参与方。

| 组别 | 同一操作与故障注入 | 必须出现的观测 |
|---|---|---|
| V01 · 动态执行 | 输入两个有不同查证需求的样本，交换工具呈现顺序；工具二的查找键由工具一运行时返回。再给一个无需继续查证或无解的输入。上限 6 次模型决策。 | 至少一次运行出现两种不同工具、两轮以上模型决策；每次工具调用有真实分派和配对的返回，后续模型收到对应结果，最终自然终止或有界停止。模型回复决定下一步。记录受控模型轨迹及每条路线与同一真实模型的兼容实测，至少捕获有效工具调用和结果回传；缺真实模型证据时整组未知。 |
| V02 · 未知能力 | 冻结两套基础运行器版本后由测试夹具向运行器提供同一个新能力及其签名。能力名、版本和测试数据此前不得出现在运行核心。每条路线分别通过直接 HTTP API、确定性工作流和动态 Agent 调用同一注册实现。另测输入非法、未发布和撤权。 | 三种入口得到语义一致的结果与业务权限。前两种入口的模型调用计数为零。新能力共用一个实现。保留注册前后 diff，区分能力包、注册配置、公共契约、持久化迁移和框架核心；若确需改核心，如实记录并说明是否满足 AC-17。 |
| V03 · 撤权 | 授权正控后独立重置并分别设屏障：下一次受限读取前、已读后发模型前、已读后发工具前、正式写入前、受限结果交付前。正式写入与交付独立注入。另测缓存中已存在旧资料。外部控制进程等待撤权事务提交后才释放屏障；覆盖暂停恢复与连续执行两态。 | 被撤权限对应的后续动作计数为零。以对应收端或存储的原始记录证明未读、未发、未写、未交付；状态可说明阻断原因，不能仅断言接口返回 403。撤权前合法已发生的事实可对账。 |
| V04 · 不确定结果与恢复 | 独立合成供应商先真实提交，再丢回执；在持久提交之后强制终止本路线实验 Worker 进程，使用新的进程从原存储恢复。覆盖可查回执、无法确认、父任务取消后迟到成功回调、重复回调；用屏障控制先后。 | 供应商独立库对同一操作只发生一次副作用；记录发送请求数、查单数、原/新 Worker 标识、历史事件和最终账本。一旦派发结果未知，不盲重发。收到可信回执后只对账，不能确认时保留未知与相关预留。取消传播且后续任务未启动；迟到/重复回调不重复结算，不把已取消父任务改回成功。 |
| V05 · 质量校验 | 两个固定必需项只完成一个，工具返回协议与结构均成功。另给错误证据版本、校验器不可用、完全满足条件四组输入。 | 负例有缺项或明确待核原因，在产品状态、交付箱和正式提交接收端均无成功交付。正例一次成功。保存校验规则版本、原始输出、判定与最终状态，区分已经发生的工具副作用和是否可交付。 |
| V06 · 并发共享预算 | 同一父任务额度 5，每个子任务预留 3，三名子任务同步发起竞争；首次持有预留者暂停，等待其余两者尝试后再释放屏障，实际消耗 2，随后处理余量。另跑父任务取消、持有预留时崩溃、重复计量和子任务迟到完成。 | 初次竞争仅一份 3 单位预留获准；并发确有重叠，每次提交账本满足“已结算 + 未释放预留 ≤ 5”。接收端独立计量证明无免费旁路；重复计量不重复扣款，不确定消费不提前退还。取消后不再新派发，子项结果、取消/阻断原因与父任务汇总一致。 |

V02 采用同一份独立测试夹具。可将挑战的具体签名和值密封、预先登记摘要，让自动化测试在每条路线公共核心冻结后解封。A 运行后先封存原始记录，仅反馈是否执行和所需改动类别；B 核心冻结前不把 A 的具体能力样例、补丁或实现交给 B。若某次解封使后续实现者接触了挑战内容，在双方核心均固定后用新的同一挑战重测两路。记录核心冻结、解封、安装及改动的先后顺序。

## 判定与工程代价

每组结果为通过、失败、未知。启动后观察到与断言相矛盾的结果记失败。环境阻断、证据不全或未运行记未知，并写出具体原因。质量正例、权限正控和原始收端证据是判定条件。修复后保留原失败记录、补丁和新运行。任何一方若需更改验收规则，先生成共同新版本并使受影响测试对双方都重跑。

仅在硬性要求取得同标准证据后比较工程代价。每条路线列出上游版本及实际调用路径、业务与公共模块、框架内核改动、持续服务、安装锁、实测失败和恢复次数；分别保存首接入及后续 V02 改动的 git diff --numstat、文件级 diff 和逐模块归类。运维负担用实际进程、镜像、存储与升级约束说明。没有实测人时不推算工期。两路均未过门槛时保留未定结论。
