# 采用依据与证据范围

资料于 2026-11-23 核对。已公开使用的机制和作者建议各有适用条件。本体系的组合、触发条件与人工交付边界是新增设计；实际采用情况由各项目实例的任务记录、独立审查和 CI 结果说明。

| 一手材料 | 公开证据及适用范围 | 本规范的采用方式 |
| --- | --- | --- |
| OpenAI Harness Engineering | 团队报告已用于实际产品工程，短仓库入口、Git 内知识、可执行边界和反馈循环确有实践记录。[团队文章](https://openai.com/index/harness-engineering/) | 根入口导航、计划和确定性检查。PR 授权、人工合并与放行沿用采用项目的决定 |
| OpenAI Agents SDK 维护团队 | 作者叙述实际维护方式，固定提交有 [AGENTS](https://github.com/openai/openai-agents-python/blob/91fb508a8931016efa793b033147d08cd20308cf/AGENTS.md)、[PLANS](https://github.com/openai/openai-agents-python/blob/91fb508a8931016efa793b033147d08cd20308cf/PLANS.md)、[implementation-strategy](https://github.com/openai/openai-agents-python/blob/91fb508a8931016efa793b033147d08cd20308cf/.agents/skills/implementation-strategy/SKILL.md)、[implementation-final-review](https://github.com/openai/openai-agents-python/blob/91fb508a8931016efa793b033147d08cd20308cf/.agents/skills/implementation-final-review/SKILL.md)、[verification](https://github.com/openai/openai-agents-python/blob/91fb508a8931016efa793b033147d08cd20308cf/.agents/skills/code-change-verification/SKILL.md)、[执行脚本](https://github.com/openai/openai-agents-python/blob/91fb508a8931016efa793b033147d08cd20308cf/.agents/skills/code-change-verification/scripts/run.sh)和 [CI](https://github.com/openai/openai-agents-python/blob/91fb508a8931016efa793b033147d08cd20308cf/.github/workflows/tests.yml)。[团队总结](https://developers.openai.com/blog/skills-agents-sdk) | 四项实现边界、独立 reviewer 回流和本地/CI 共用入口。具体测试栈及上游的 PR 写入规则由采用方自行确定 |
| OpenAI 的可恢复执行计划 | 官方 Cookbook 有仅用仓库与计划恢复复杂任务的示例。[ExecPlans](https://developers.openai.com/cookbook/articles/codex_exec_plans/) | 单一任务记录与冷恢复。实现前另设方案可行性评审是本体系的适配 |
| Google Engineering Practices | 公开团队工程准则涵盖小变更及设计、功能、复杂度、测试、命名和文档审查。[Small CLs](https://google.github.io/eng-practices/review/developer/small-cls.html) · [审查要点](https://google.github.io/eng-practices/review/reviewer/looking-for.html) | 小批量、具体反馈、原作者验证并处置 |
| Martin Fowler 的 CI | 作者总结持续小批量集成、自测试构建、及时修复与接近目标环境验证的实践。[Continuous Integration](https://martinfowler.com/articles/continuousIntegration.html) | 快速反馈、目标环境、可重现构建证据；必需门禁由采用项目定义 |
| GitHub PR、Actions 与 Rulesets | 平台文档定义草稿、合并引用、受保护分支、必需检查和最小权限等机制。[PR](https://docs.github.com/en/pull-requests/reference/pull-requests) · [规则集](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/available-rules-for-rulesets) · [Actions 安全](https://docs.github.com/en/actions/reference/security/secure-use) | Draft 交付与人工决定、检查精确候选、分层权限；服务器生效状态需现场验证 |
| C4、ADR、Diátaxis | 方法作者提供分层图、版本化决策和按读者需求组织文档的说明。[C4](https://c4model.com/) · [Michael Nygard 的 ADR](https://cognitect.com/blog/2011/11/15/documenting-architecture-decisions) · [Diátaxis](https://diataxis.fr/) | 可编辑系统/容器图，保留决策历史，按内容而非目录数量满足读者需要 |
| Peter Steinberger | 本人描述工程使用方法，公开 PR 有独立 review 和复验记录。[经验文章](https://steipete.me/posts/2025/shipping-at-inference-speed) · [PR #44](https://github.com/steipete/agent-scripts/pull/44) · [PR #392](https://github.com/openclaw/agent-skills/pull/392) | 短入口、已有命令和独立评审回流。需要时采用经验证的原生命令或项目已评审的工具 |
| Simon Willison | 作者给出以真实失败和通过验证 Agent 实现的实践。[Red/green TDD](https://simonwillison.net/guides/agentic-engineering-patterns/red-green-tdd/) | 对重要回归与确定性检查验证反例和修复，选择适合任务的测试层 |
| Codex 与 ChatGPT Space | 官方说明仓库指令、技能加载、配置、工作区、页内引用和协作权限。[AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md) · [技能](https://learn.chatgpt.com/docs/build-skills) · [配置](https://learn.chatgpt.com/docs/config-file/config-basic) · [工作区](https://learn.chatgpt.com/docs/environments/git-worktrees) · [Pages](https://learn.chatgpt.com/docs/space/pages) | 本机与会话状态分别实测，Git 维护权威规范，Space 以链接或授权更新协作材料。方案关卡利用 [Codex CLI](https://learn.chatgpt.com/docs/non-interactive-mode)的新会话、只读权限和结构化输出，由本体系实现结果判定 |

源文档更新后核实影响机制的事实，重要版本变更保留稳定提交引用。只读评审、采用记录和运行测试共同说明候选实际成熟度。
