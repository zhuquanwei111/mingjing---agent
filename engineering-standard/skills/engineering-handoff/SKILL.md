# 工程任务接续

输入为当前 Git 工作区和已有任务记录位置。用户只给任务名时，从项目规则和任务索引定位记录。存在多个实质不同的任务候选时，核对当前分支并请用户确认目标。

1. 先读根 `AGENTS.md` 和任务记录，使用项目已有只读检查。需要通用命令时，从 Git 根运行 `git status --short --branch`、`git rev-parse --show-toplevel HEAD`，再按本次授权核对相关差异与 PR 状态。
2. 核实目标、验收、允许动作、当前候选、未提交修改、待办和阻断。计划中的旧 SHA 或通过结果须关联到实际候选。保留其他工作区和并行任务的修改。
3. 恢复时说明目标、实际分支与状态、已核实证据及首个安全动作。只读验证仅执行授权范围内的安全核对，明确回报恢复是否完成。继续实施时执行第一条已获授权且适用于当前状态的步骤。重要信息不足时写明具体缺口。
4. 交接时更新原任务记录的当前状态、验证和下一步，给出可定位的记录路径。会话、任务和用户批准分别以实际授权为准，记录和技能本身不会授予外部写入权限。
