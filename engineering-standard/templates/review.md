# 独立评审交接

默认由主 Agent 发起**独立上下文的原生子代理**（建议角色 `solution_reviewer`，模板见 [../agents/solution-reviewer.toml](../agents/solution-reviewer.toml)）；支持时使用 `fork_turns: "none"`，不继承设计聊天历史。不支持时启用独立新会话。评审者读取指定版本的原始需求和方案，不修改项目；**不要求强制只读权限证明**，但核对任务完整送达、材料证据和实际回流。子代理角色继承主会话权限，文字约定不等于硬沙盒。小型低风险任务允许轻量评审。

## 方案评审角色

原生子代理角色 `solution_reviewer`（旧 CLI 关卡的回执角色仍为 `solution-reviewer`，其协议不变）。主 Agent 发起审查、等待回执，然后将问题交给**原设计者**处置；原设计者若就是主 Agent，直接由主会话修订。评审者确认完整接收请求，先读指定需求、候选方案、项目根规则及相关实现。回执包含角色、触发请求的短标识、两个版本、审查范围及至少一条确实来自指定资料的证据。创建成功、通用应答、仅复述请求或缺少回执时，原设计者停止提交实施步骤，核对任务投递或改用全新独立会话（可用时选只读权限）。

## 方案评审请求

> 评估已固定的需求 <路径、版本与 SHA256> 和候选 <路径、版本与 SHA256>。项目根与基线为 <位置、SHA>，权威规则与当前实现入口为 <路径>，只核对 <范围>。收到后按角色提交 <短标识> 及材料证据。请独立读取这些材料和相关代码。按需求、兼容、权限、依赖、环境、成本、失败与回退判断可行性。提供具体文件或命令证据，用可实施、需修改、需实测或阻断给出结论。只作已授权的只读核对，由原设计者处置结果。

没有真实回执或审查结论时，不得假称已通过；设计者修订了被审方案或重要基线后，需要重审受影响部分。不能自动回流时允许用户手动转交评审报告，不因此另外开发桥接器。

回传每条问题的类型、证据和处理建议。类型包括阻断性问题、必要修正、可选建议及待实测假设。进入实现前应处置已确认的阻断、必要修正及影响可行性的待实测假设；可选建议可记录原因后暂缓。需求、候选、实际命令或相关基线变化时按受影响范围重新评审。
